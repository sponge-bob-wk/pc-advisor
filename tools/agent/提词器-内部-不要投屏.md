> 用途：上台讲解 / 投屏展示。全文按"讲得下去"的顺序排，每节末尾有 **讲点**（那一段你该说什么）。
> 配套：现场操作看 `演示脚本-2026-11-12.md`；技术细节看 `PRD-选机决策智能体-v1.0.md`（v1.1）。

## 〇、30 秒讲清（开场就用这段）

> 这是一个给准大学生的**对话式选购助手**：说清预算和用途，它给**一台具体机型**，
> 并且**先告诉你这台在你用途下的短板**。
>
> 它最值钱的不是"知道得多"，是**"说出口的每一句都站得住"**——
> 每个数字都能追到数据源，追不到的，它明说没有。

**讲点**：不要一上来讲技术。先让人记住一句话——"它不是推荐引擎，是一条能核对的推导链"。

---

## 一、要解决的问题（先讲问题，再讲功能）

准大学生买第一台电脑，卡在四件事上：

| 他们遇到的 | 现有方案为什么不行 |
|---|---|
| 参数表看不懂 | 电商页面只列参数，不解释"这对你意味着什么" |
| 测评像恰饭 | 所有人都在说"值得买"，但没人给依据 |
| 价格口径乱 | 划线价 / 券后价 / 国补价 / 到手价混着写 |
| **最怕这一条** | 推荐了一台**不适合我专业**的机器，还说它好 |

**讲点**：第四条是真正的痛点，也是这个产品的起点——
不是"信息不够"，是**"没有一句能站得住的话"**。

---

## 二、目标用户

- **主要**：准大学生，预算 4000–8000，第一次自己买电脑，不懂参数，怕被坑
- **次要**：帮孩子选电脑的家长，只关心"够不够用、多少钱、有没有坑"
- **共同行为**：会追问、会怀疑、会当场改主意，**没有耐心读参数表**

**讲点**：注意"会当场改主意"——这决定了产品必须能接住半句话和改条件，
后面"不做的功能"里有一条就是为此。

---

## 三、核心功能（P0，必须有）

> 状态：5 条**全部已实现**，2026-11-12 实测通过。

1. **对话式推荐**
   说"预算 + 用途"（可以分几轮说），给 1 台首选 + 2 台候选，含机型、完整配置、到手价。

2. **短板前置**
   这台机器在**你当前用途下**的硬伤，必须写在推荐理由**前面**，不允许只夸优点。

3. **追问不编**
   问屏幕 / 保修 / 重量 / 够不够用，只答数据里有的；没有就明说"库里没有"，并告诉你该去哪儿查。

4. **出口审计**
   回答里的数字必须能追到内核或用户原话；无出处的评价词、库外机型，一律拦掉重写。

5. **数据概览侧栏**
   把"这个库到底有多少料"摊开：97 台里 22 台有人写过优缺点、75 台只有参数；价位段分布、跑分与重量覆盖度。侧栏可收纳。

**讲点**：第 2 条和第 4 条是"反行业习惯"的——大多数推荐产品先夸优点，
它必须先说短板；第 4 条意味着**模型没有数字写权限**，说错话会被自己的规则打回。

---

## 四、P1 / P2（先讲边界，再讲增量）

**P1（应该有，已实现 4 条）**
- **专业路径**：报专业（如"人工智能"）→ 查专业配置表，给出内存底线 / 推荐档、是否必须可加装、显卡是否设门槛，并指出这台差在哪
- **同类对比**：三台放一起，比价格 / 跑分 / 内存 / 重量 / 可加装；缺数据写"未知"，不补 0
- **清单模式**：说"把其余推荐列出来"，输出第 2、3 名清单，标注是否有人写过优缺点
- **价格拆解**：页面价 → 券 → 国补 → 到手价，逐步可核对

**P2（锦上添花，已实现 2 条）**
- 重量比较：报这台 kg + 同品类同预算区间（学生几乎都要带出门）
- 深链分享：`/?q=学设计的，预算5100` 直接把问题带给对方
- （未做）显式的"把这两台比一下"按钮，现在只能靠打字问

**讲点**：主动说"有一条没做"。这比宣称"全做完"更能建立信任，
也顺便说明这套东西有真实的优先级判断。

---

## 五、不做的功能（这一页最能体现思考）

- **不做排行榜 / 综合评分 / 雷达图** —— 库里没有"综合分"这个字段，做了就是编
- **不做手机 / 平板 / 工作站 / Mac** —— 库外品类，遇到直接拒答，**不许拿别的机器顶替**
- **不做帧数 / 续航小时 / 返修率 / 色准 ΔE** —— 这四项没有数据，问了就答"没有"
- **不做登录注册 / 云同步 / 移动端 App** —— 个人工具场景，先把一件事做对
- **不让前端算数** —— 排名、差价、百分比、平均数一律后端算，前端只画
- **不改数据文件** —— 数据零写权限，发现冲突记进文档，等人裁决
- **不引入框架 / 构建工具 / CDN** —— 单文件 HTML，双击就能开
- **不说"AI 精选""大数据推荐"** —— 它不是推荐引擎，是推理链

**讲点**：挑两条重点讲——"不编帧数"和"不做综合评分"。
这两条是同行最容易做的，也是这个产品**故意不做**的。

## 六、用户流程（现场要走的 6 步）

1. 打开网页 → 看到一句话说明 + 三个数（97 / 22 / 4 类）+ 输入框
2. 输入「学设计的，预算 5100，要带去教室」→ 一台首选 + 短板 + 到手价 + 三台对比
3. 追问「屏幕怎么样」→ 只答屏幕；没人评过就明说"我只报参数"
4. 问「这台行不行」→ 给匹配度判定，**不换台**
5. 说「把它和另外两台放一起比」→ 并列对比，缺数据标"未知"
6. 问「推荐个手机」→ 拒答：只做 Windows 笔记本 / 台式整机 / 内存固态

**讲点**：第 3 步和第 6 步是"可信度"的两面——
一个证明它不编，一个证明它敢说"不"。

---

## 七、技术约束（一句话版）

- **分工是硬边界**：排序在内核（纯函数，模型无权改）→ 措辞在组装层（模型只说人话）→ 出口审计（拦编造）
- 前端：单文件 `index.html`，无框架、无构建、无 CDN
- 后端：Python 标准库 `http.server`，端口 7860，只绑本机
- 模型：本地 Ollama `qwen3.5-4b`，`temperature=0`（它只做转述，不做创作）
- 数据：`prices.json`(22) + `machine_pool.json`(80) + `bench.json` + `majors.json`，**只读**

**讲点**：如果被问"为什么用这么小的模型"——因为决策不在模型里，
它只负责"把结果说成人话"，4B 够用，还能本地跑、可复现。

---

## 八、成功标准（可现场验证）

1. 输入「学设计的，预算 5100，要带去教室」→ 给出具体机型 + 到手价 + 至少一条短板
2. 同一台换 4 个入口问（首推 / 追问 / 够不够用 / 点名问）→ 说法一致，不串台
3. 问库里没有的（保修年限 / 帧数 / 续航）→ 明说没有，并给出去哪儿查
4. 问库外品类（手机 / 平板 / Mac）→ 拒答，不拿别的机器糊
5. 推荐理由里不出现"高达 / 首选 / 性价比高 / 值得买"（除非这台真有人工评价）
6. 后端 802 项测试全绿 + 60 条乱测夹具 0 违规，数据一致性检查 0 条
7. `python server.py` 起服务 → 打开网页就能用；模型离线时降级为模板回答

**讲点**：这 7 条都能当场验，不是"设计目标"，是"实测通过"。

---

## 九、已知边界（主动说，别等人问）

1. 库只有 **97 台**（22 台人工核定 + 75 台采集），不是全网比价
2. **6 处价格冲突未裁决**：页面标"未裁决"，系统不替用户选哪个价是对的
3. **5 个 CPU 缺换算分**，宁可标"无跑分"，也不自己发明换算系数
4. 人工那 22 台**没有实测重量**，所以重量比较只覆盖采集池
5. 没有"按显卡/显存筛选"的硬约束：说"非要独显"时，它只能讲清"这个预算的轻薄本没有"，再问你要不要看游戏本

**讲点**：这一页是"诚实度"的证明。
说清"我们做不到什么"，比说"我们什么都能"更让人敢用。
