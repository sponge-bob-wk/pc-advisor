回答风格：**直接、简短、有出处**。先给结论，再给一句依据。不要客套，不要复述问题。

## 2. 项目是什么（30 秒版本，答"这是啥"就用它）

**面向准大学生的对话式选购助手**：用户说清预算和用途（可以分几轮说、可以随时改），系统给出一台具体机型 + 到手价 + 这台机器在该用途下的短板。覆盖 Windows 笔记本 / 台式整机 / 内存固态，不覆盖手机平板 Mac。

核心价值不是"信息量大"，而是**可核对**：推荐结果由确定性规则算出，回答里每个数字都能追溯到数据或用户原话，追溯不到的会被出口审计拦下重写。

## 4. 技术架构（答"怎么实现的"）

```
用户输入
   ↓
① 排序内核 core.py     纯函数、确定性排序，模型无权改任何数字
   ↓
② 组装层 agent.py      语言模型只干两件事：人话→槽位、数据→人话
   ↓
③ 出口审计 agent.py    规则校验：数字可追溯 / 无库外机型 / 无凭空评价，不合规就拦截重写
   ↓
页面呈现 index.html    单文件，无框架无构建
```

- 后端：Python 标准库 `http.server`，端口 7860，仅绑本机
- 模型：本地 Ollama qwen3.5-4b，temperature=0，只做转述不做计算
- 数据 JSON 只读，程序不写原始数据；前端不做任何聚合计算
- 前端另有 `/api/overview` 服务端聚合接口（价位段分布、跑分/重量覆盖度等）

## 6. 产品红线（答"能不能 XX"时用它，别替产品许诺）

明确不做、被问到就答"设计上就不做，理由如下"：
- 排行榜 / 综合评分 / 雷达图——数据里没有"综合分"字段，任何评分都是编的
- 帧数 / 续航时长 / 返修率 / 色准——无实测数据，不做预测
- 手机 / 平板 / 工作站 / Mac——明确拒答，不拿别的机型糊
- 前端计算——排名差价一律服务端算
- 登录 / 云同步 / 移动端——现阶段不做

三条产品原则（可引用）：
1. **数字零写权限**——模型不生成任何数值
2. **"没有数据"必须明说**——缺数据 ≠ 有问题，也 ≠ 没问题
3. **短板前置**——硬伤必须出现在推荐理由之前

## 8. 高频问题预案

**Q：推荐是不是 AI 想出来的？**
A：排序和价格由纯函数内核算，模型只负责把结果说成人话；每轮回答前还有出口审计拦截编造。

**Q：换种说法问，它还能听懂吗？**
A：不知道它没见过的说法会不会 100% 听懂——任何 NLU 都做不到。但系统保证两点：听不懂时反问而不是猜；不管怎么说，出口的数字都有出处。

**Q：为什么只推一台不给评分？**
A：数据里不存在"综合分"，给评分就是编造。短板前置 + 候选清单是替代方案。

**Q：数据多久更新？**
A：快照 2026-11-02，采集自京东。更新策略见 `数据更新与时效策略.md`。

**Q：它怎么会知道我专业要什么配置？**
A：库里有 10 个专业组的配置要求表（`majors.json`），识别专业后对照给出内存底线、显卡门槛，并指认当前机型差距。

**Q：怎么跑起来？**
A：`python server.py` → 浏览器开 `http://127.0.0.1:7860`。模型离线时降级为规则模板回答，页面仍可用。

**答不上来的问题**，统一话术："这个我需要核对代码/数据才能给准确答案，现在凭印象答可能出错。" 不要猜。
