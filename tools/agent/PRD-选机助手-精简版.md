# 选机助手

## 一句话描述

一个给准大学生用的**对话式笔记本选购助手网页**：说清预算和用途，直接给一台具体机型 + 到手价 + 这台在你用途下的短板，每个数字都能追到数据源。

---

## 目标用户

- **主要**：准大学生（预算 4000–8000，第一次买电脑，看不懂参数，怕被坑，怕买到不适合自己专业的）
- **次要**：帮孩子选电脑的家长（只关心"够不够用、多少钱、有没有坑"）
- 共同特征：会追问、会怀疑、会当场改主意；没有耐心读参数表

---

## 要解决的问题

1. **参数表看不懂**：i5-13420H 和 Ultra5-225H 差在哪，没人用他能懂的话说
2. **测评不可信**：看起来都像恰饭，"值不值得买"这句话没有出处
3. **价格口径混乱**：划线价、券后价、国补价、到手价混在一起
4. **最怕这一条**：推荐了一台**不适合我专业/用途**的机器，还说它好

> 一句话：不是"没有信息"，是**没有一句能站得住的话**。

---

## 核心功能（P0，必须有）

> 状态：5 条**全部已实现**（2026-11-12，802 项测试全绿 + 60 条乱测夹具 0 违规）。

- **对话式推荐**：用户说"预算 + 用途"（可分批说），系统给 1 台首选 + 2 台候选，含机型、完整配置、到手价
- **短板前置**：这台机器在**当前用途下**的硬伤，必须写在推荐理由前面，不允许只夸优点
- **追问不编**：问屏幕/保修/重量/够不够用，只答数据里有的；没有就明说"库里没有"，并告诉他去哪儿查
- **出口审计**：回答里的数字必须能追到内核或用户原话；无出处的评价词、库外机型一律拦掉
- **数据概览侧栏**：97 台库里"22 台有人写过优缺点 / 75 台仅参数"，价位段分布、跑分与重量覆盖度；侧栏可收纳

## P1（应该有，P0 通过后做）

> 状态：4 条**全部已实现**。

- **专业路径**：用户报专业（如"人工智能""计算机科学与技术"）→ 查专业配置表，给出内存底线/推荐档、是否必须可加装、显卡是否设门槛，并指出这台差在哪
- **同类对比**：三台放一起，比价格/跑分/内存/重量/可加装；缺数据写"未知"，不补 0
- **清单模式**：用户说"把其余推荐列出来"，输出第 2、3 名清单，标注是否有人写过优缺点
- **价格拆解**：页面价 → 券 → 国补 → 到手价，逐步可核对

## P2（可以有，锦上添花）

> 状态：3 条里 2 条已实现，「比一下」按钮还没做。

- **把这两台比一下**：目前只能靠打字问，没有按钮（未做）
- 重量比较：报这台 kg + 同品类同预算区间（学生几乎都要带出门）
- 深链分享：`/?q=学设计的，预算5100` 直接把问题带给对方

---

## 不做的功能

- **不要登录注册**（个人工具场景，不需要账号体系）
- **不要云端同步、不要移动端 App**（先做桌面网页）
- **不要排行榜、综合评分、雷达图**（库里没有"综合分"这个字段，做了就是编）
- **不要手机 / 平板 / 工作站 / Mac**（库外品类，遇到直接拒答，不许拿别的机器顶替）
- **不要帧数 / 续航小时 / 返修率 / 色准 ΔE**（这四项目前没有数据，问了就答"没有"）
- **不要前端自己算数**（排名、差价、百分比、平均数一律由后端算，前端只画）
- **不要改数据文件**（`data/*.json` 零写权限，发现冲突记进文档等人裁决）
- **不要引入框架 / 构建工具 / CDN**（单文件 HTML，双击就能开）
- **不要"AI 精选""大数据推荐"这类营销话**（它不是推荐引擎，是推理链）

---

## 用户流程

1. 用户打开网页 → 看到一句话说明 + 三个数（97 台 / 22 台有人评过 / 4 类）+ 输入框
2. 用户输入"学设计的，预算 5100，要带去教室" → 得到 1 台首选 + 短板 + 到手价 + 三台对比表
3. 用户追问"屏幕怎么样" → 只答屏幕；库里没人评过就明说"我只报参数"
4. 用户问"这台行不行" / "把其余推荐列出来" / "把它和另外两台比一下" → 分别给判定、清单、对比
5. 用户问"推荐个手机" → 明确拒答：只做 Windows 笔记本 / 台式整机 / 内存固态

---

## 技术约束

- **前端**：单文件 `index.html`（内联 CSS/JS），无框架、无构建、无 CDN
- **后端**：Python 标准库 `http.server`，端口 **7860**，只绑 `127.0.0.1`
- **模型**：本地 Ollama `qwen3.5-4b`，`temperature=0`；模型只做两件事——人话→槽位、数据→人话
- **数据**：`data/*.json` 只读（prices 22 台人工核定 + machine_pool 80 台采集 + bench 跑分 + majors 专业配置表）
- **界面语言**：中文
- **关键分工（硬边界）**：排序在 `core.py`（纯函数，模型无权改）；措辞在 `agent.py`；出口审计在 `agent.py`

---

## 成功标准

> 以下 7 条 2026-11-12 全部实测通过，不是设计意图。

- 输入"学设计的，预算 5100，要带去教室" → 给出一台具体机型 + 到手价 + 至少一条短板
- 同一台换 4 个入口问（首推 / 追问 / 够不够用 / 点名问）→ 说法一致，不串台
- 问库里没有的（保修年限、帧数、续航）→ 明说没有，并给出去哪儿查
- 问库外品类（手机 / 平板 / Mac）→ 拒答，不拿别的机器糊
- 推荐理由里不出现"高达 / 首选 / 性价比高 / 值得买"（除非这台真有 22 台层的人工评价）
- 后端 802 项测试全绿（另有乱测夹具 60 条 0 违规），`audit_data` 0 条，数据文件 mtime 不变
- 页面能自己跑：`python server.py` → 打开 7860 即可用，模型离线时降级为模板回答
