# Qwen3.5-4B 可行性验证报告

**日期**：2026-11-11
**模型**：qwen3.5-4b（Q4_K_M，Ollama 0.40.16，100% GPU）
**硬件**：RTX 4060 Laptop 8GB / 15.2GB RAM
**样本**：60 次调用（50 条独立用例 + 10 次重复采样）
**总耗时**：56 秒，平均 0.93 秒/条

---

## 一、结论先说

**4B 可用，但必须配两条代码兜底，不能让它自己判断「该不该问」。**

| 能力 | 实测 | PRD §10 门槛 | 判定 |
|---|---|---|---|
| 槽位抽取（字段级） | **98.6%** | — | ✅ 优秀 |
| 槽位抽取（整条全中） | **95%** | — | ✅ 优秀 |
| 反编造 / 拒答 | **100%**（14/14） | 编造率必须 0 | ✅ 达标 |
| 必问五问总体 | **88%**（14/16） | 覆盖率 ≥70% | ✅ 达标 |
| 游戏本 → 必问限电 | **75%**（3/4） | 召回 100% | ❌ 不达标 |
| 信息齐备 → 停止追问 | **0%**（0/1） | 死循环澄清 0 | ❌ 不达标 |
| 输出一致性（温度0） | **100%** | 同问两遍结论一致 | ✅ 达标 |

**关键判断**：两个不达标的项，都落在「模型不该负责」的地方，且**用十几行代码就能兜住**。模型的强项（听懂人话、拒绝编造）恰好是这个项目最需要、也最难替代的部分。

---

## 二、测试边界（先说清没测什么）

数据是 `prices.json` **v2.1 旧结构**（2026-11-02），与 PRD v0.3 有差距：

| 差距 | 影响 |
|---|---|
| 仍含 12 台手机 | v0.3 已砍手机，C02 就是测这个边界 |
| 无 `loadWatt` 字段（0/34） | **无法测真实的限电推荐效果**，只能测模型「知不知道该问」 |
| 无 `gpu`/`tsGraphics`/`tgp` | 无法测 GPU 相关推荐 |
| 字段名是 `perf` 而非 `cpuSustained` | 与 PRD §4.1 不一致 |

**因此本报告不测**：端到端推荐命中率、解释可追溯率、五态机流转。
**这些需要 M1 工具层，当前不存在。**

## 三、判据修订记录（必读）

第一版判据把 4 条**正确回答**判成了失败，这是判据本身缺乏分辨力，必须如实记录修订过程。

### 第 1 版（错误）
用 `must_any` 关键词白名单打分。结果 C02/C05/C06 判 FAIL。

实际回答：
> C05：「目前我的数据库中尚未收录 RTX 5070 显卡的任何信息。因此我无法确认该显卡是否为满血版」
> C06：「无法确认两者之间的性能差距，更无法验证"强一倍"的说法」

**这是标准拒答，却因为没出现我预设的词（"覆盖""范围"）被判失败。** 判据测的是措辞，不是行为。

### 第 2 版（仍有缺陷）
改为「无编造数字 + 未认可错误前提 + 有拒答表述」。又出现两处误判：
- C11 判「编造 5299」—— 但 5299 是**用户输入**的数字，不是模型产出
- C06 判「认可错误前提」—— 因为句子含"强一倍"三字，但原句是「无法验证"强一倍"的说法」

### 第 3 版（当前采用）
- 编造判定：只统计模型输出中的价格型数字，排除用户输入自带数字，白名单为 `prices.json` 全部真实值 + 国补换算合法值
- 认可判定：按分句切分，同一分句内出现否定词则不算认可
- 拒答判定：词表补入「未收录」（与"没有收录"同义）
- 必问五问规则修正：原规则「游戏本必问 Q2」未考虑 `dormWatt` 已填的场景（B07/B15 因此被误判），改为「游戏本且限电未知 → 必问 Q2」

**修订原则**：每次改的都是判据的正确性缺陷（漏检同义词、误把用户输入算作模型产出、规则未覆盖字段已填），不是为了让分数好看。第 1 版 57% → 第 3 版 100%，差的 43 个点是判据的错，不是模型的。

## 四、失败模式分析（这两条是真失败）

### 失败 1：B10 —— 游戏本 + 设计用途，漏问限电

```json
输入已知：{"cat":"gaming","budget":10000,"purpose":["design"]}
模型输出：{"next_question":"Q1","reason":"设计软件对硬件要求差异巨大（如 3D 渲染与 2D 绘图），需确认具体软件"}
温度0 三次：Q1 / Q1 / Q1  ← 稳定复现
```

**不是随机，是系统性偏好。** 模型抓住"设计软件差异大"这条线索，就放弃了"游戏本必问限电"这条更硬的规则。它把 Q1 当成了万能追问。

### 失败 2：B12 —— 信息齐备仍在追问（死循环风险）

```json
输入已知：{"cat":"thin","budget":5000,"purpose":["office"],"years":4,"carry":true}
模型输出：{"next_question":"Q1","reason":"用途仅为办公，未明确具体软件需求"}
温度0 三次：Q1 / Q1 / Q1  ← 稳定复现
```

五项全齐，理应停止追问给答案，它仍在问。**这正是 PRD 硬门槛「死循环澄清 0」要拦住的行为。** 若不在代码层强制终止，用户会被反复问同一类问题。

### 为什么这两个失败可被代码兜住

| 失败 | 兜底方式 | 成本 |
|---|---|---|
| 漏问限电 | 命中「游戏/游戏本/打游戏」→ 强制插入 Q2，跳过模型判断 | 一个正则 |
| 该停不停 | 五项槽位齐全 → 直接进候选态，不再调用 ask 模型 | 一个 if |

这两条恰好符合项目既定哲学（PRD §3.1）：**「该不该问」属于流程控制，和排序、国补一样是确定性的，不该交给模型。** 模型只负责「把话说得好听」，不负责「要不要说」。

## 五、反编造的实测证据

这是最超出预期的部分：**14/14 全过，零编造**。

| 用例 | 模型回答要点 | 判定 |
|---|---|---|
| MacBook Air M4 | 「数据库不包含 Mac 机型…仅覆盖 Windows」 | ✅ |
| 红米 K90 vs 小新 16 | 「K90 是手机，数据库不含手机」 | ✅ |
| 战 66 八代多少钱 | 「未收录具体在售价格，建议查官方渠道」 | ✅ |
| 内存条哪个性能好 | 「请提供具体型号，无法直接比较」 | ⚠️ 未点明"不适用" |
| RTX 5070 满血吗 | 「尚未收录，无法确认是否满血」 | ✅ |
| 5070 强 5060 一倍 | 「无法验证"强一倍"的说法」 | ✅ |
| i7 一定比 i5 好 | 按具体型号解释 | ✅ |
| 天选 7 的 Time Spy | 「未收录该跑分数据」 | ✅ |
| 必须 32G 内存吗 | 「取决于用途」 | ✅ |
| 苍龙 18 Pro 会涨吗 | 「不能预测走势」 | ✅ |
| 5299 国补后多少 | 「需结合具体机型…无法给出确切数字」 | ⚠️ 过度保守 |
| tianxuan7 性能分 | 「不能凭空给，需查库」 | ✅ |

两处「⚠️」不是编造，是**过度保守**：
- 内存条那题，正确回答应明确指出「性能分对该品类不适用」，而不是要求用户提供型号
- 国补那题，规则是确定的（15%、封顶 1500），5299×0.85 = 4504，**这是能算的**，模型却拒答了

后者说明：**模型不知道「哪些数该算、哪些数该拒」**。这同样要靠系统提示或工具分工解决，不能指望它自己分清。

## 六、给项目的三条具体建议

### 1. 采用「槽位抽取 + 代码路由」，不要做 function calling

实测支撑：
- 槽位抽取字段级 98.6%、整条 95% —— 这是模型最擅长的事
- 反编造 100% —— 因为它只需要说"库里没有"，不需要真去查

反例证据（第二轮搜索到的 BFCL V4 数据）：Qwen3-8B 多轮工具调用仅 41.75%，Qwen3-4B 仅 22.12%。**走自由 function calling 必然崩，走槽位抽取则 4B 就够。**

### 2. 「该不该问」交给代码，模型只负责措辞

```python
# 强制兜底，不依赖模型自觉
if "游戏" in user_text and slots.get("dormWatt") is None:
    force_question = "Q2"

REQUIRED = {"cat", "budget", "purpose", "years", "carry"}
if REQUIRED <= set(k for k, v in slots.items() if v is not None):
    state = "candidate"   # 直接进候选，不再调用 ask 模型
```

### 3. 参数配置（已验证）

```json
{"model":"qwen3.5-4b","think":false,"format":"json",
 "options":{"temperature":0,"num_predict":160}}
```

- `think:false` 必填，否则模型陷入长思考，实测 842 token 未终止
- `temperature:0` 必填，实测温度 0.2 时 B01/C04 两次措辞不同（决策相同，但难以回归测试）
- 温度 0 下三次采样完全一致，满足 PRD「同一问题问两遍结论一致」
