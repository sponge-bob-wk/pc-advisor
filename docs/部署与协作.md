# 部署与协作：一台机器，两种人

> 场景说明（2026-11-13 确定）：**模型只跑在维护者这台机器上**。
> - 组内成员：clone 代码改功能，提 PR；本地**不需要**大模型也能跑测试和改前端
> - 测试同学：**只需要一个链接**，不用装任何东西
> - 维护者：负责起服务、发链接、收日志、筛训练样本

---

## 一、角色与权限

| 角色 | 拿到什么 | 不做什么 |
|---|---|---|
| **维护者（我）** | 起服务、发链接和访问码、看日志、筛样本 | 不改 `data/*.json`（数据另有核实流程） |
| **组内成员** | 仓库读写（PR）、可选的公网链接 | 不长期起服务、不碰数据、不改判据不加对照 |
| **测试同学** | 一个 `https://.../?k=码` 链接 | 不用装环境、不用注册 |

> 测试同学的每一轮都会进 `logs/`，带 `uid` 区分是谁。这就是后续训练样本的来源。

## 二、起服务（维护者）

### 2.1 只给自己用

```bash
cd tools/agent
python server.py            # http://127.0.0.1:7860
```

### 2.2 给局域网的人用

```bash
ACCESS_CODE=一个码 python server.py --lan
```

会打印 `http://192.168.x.x:7860` 和访问码。同 WiFi 的人打开
`http://192.168.x.x:7860/?k=访问码` 即可。

⚠️ 学校/公司 WiFi 常开启"终端隔离"，局域网互访可能不通 —— 那就走方式 B。

### 2.3 给外网的人用（临时链接，零成本）

```bash
# 安装（三选一）
winget install Cloudflare.cloudflared
# 或 scoop install cloudflared
# 或去 GitHub releases 下 cloudflared-windows-amd64.exe 改名 cloudflared.exe 放进 PATH

# 起隧道（另开一个窗口，服务要一直开着）
cloudflared tunnel --url http://127.0.0.1:7860
```

输出里会有一行：

```
https://random-three-words-1234.trycloudflare.com
```

发链接时带上码：

```
https://random-three-words-1234.trycloudflare.com/?k=你的访问码&u=张同学
```

`u=` 是可选的昵称，会记进日志的 `uid`，方便你分清谁提的问题。

**临时隧道的三个坑**：

1. 每次重启 `cloudflared` 都会换域名 —— 发出去前先自己点一遍
2. 电脑睡眠/关机 = 链接立刻失效（隧道进程和 Python 服务都得活着）
3. 免费隧道有并发与带宽限制，多人同时问会排队；本机模型本来就一次只能答一个人

### 2.4 固定域名（长期，可选）

要一个不变域名，两条路：

**A. Cloudflare Named Tunnel（需要自己的域名托管在 CF）**

```bash
cloudflared tunnel login
cloudflared tunnel create pc-advisor
cloudflared tunnel route dns pc-advisor advisor.example.com
cloudflared tunnel run --url http://127.0.0.1:7860 pc-advisor
```

**B. frp + 一台小服务器**

```
# 服务器 frps.ini
[common]
bind_port = 7000

# 本机 frpc.ini
[common]
server_addr = 你的服务器IP
server_port = 7000
[web]
type = tcp
local_ip = 127.0.0.1
local_port = 7860
remote_port = 17860
```

nginx 反代到 443 + 证书，再在服务端加 `ACCESS_CODE`。

### 2.5 启动脚本

**双击就能用**，不用记命令。项目根目录四个入口：

| 文件 | 干什么 |
|---|---|
| `启动助手.bat` | 菜单，选本机 / 局域网 / 公网三种模式 |
| `一键公网链接.bat` | 直接生成公网链接，跳过菜单 |
| `停止服务.bat` | 停服务 + 隧道，释放端口 |
| `环境检查.bat` | 只检查不启动 |

底下的壳是 `scripts/launcher.bat` → `tools/launcher.py`。

> 为什么不用 bat 直接写逻辑：① bat 里的中文靠 `chcp 65001` 撑着，
> 时不时乱码，而报错那几行恰恰最需要看清；② 公网模式要**抓隧道地址并拼好
> `?k=`**，bat 做不到；③ bat 没法做端口/进程的前置检查。
> 详见 [`启动与部署.md`](./启动与部署.md)。

命令行等价形式：

```bash
python tools/launcher.py local|lan|public|stop|check
```

## 三、访问码与身份

| 机制 | 实现 | 说明 |
|---|---|---|
| 访问码 | 环境变量 `ACCESS_CODE`；前端从 `?k=` 读一次存 localStorage，之后每个请求带 `X-Access-Code` 头 | 不设 = 不校验。**公网暴露必须设** |
| 客户端标识 | 浏览器生成随机串存 localStorage；`?u=昵称` 可覆盖；每个请求带 `X-Client-Id` | 只用于区分日志来源，不是账号，不收集个人信息 |

服务端在 `/api/*` 上校验访问码，**页面本身不拦**（否则连输码的机会都没有）。
前端拿到 401 会直接提示"需要访问码"。

## 四、日志与训练样本（维护者每天做的事）

### 4.1 日志长什么样

`tools/agent/logs/chat-YYYY-MM-DD.log`，一行一轮：

```json
{"text":"学设计的，预算5100","known":null,"uid":"tester01","ok":true,"ms":2838,
 "stage":"recommend","slots":{"cat":"thin","budget":5100},"picked":"联想小新 16",
 "reply":"...","warnings":[],"issues":[],"ts":"2026-11-13T10:31:00.000"}
```

- `issues` 非空 → 出口审计当场发现问题（编造词 / 数据外数字 / 库外机型）
- `uid` → 谁问的

**这些日志不入库**（`.gitignore` 已排除）：里面有测试同学的真实提问，属于他们的数据。

### 4.2 把日志筛成样本

```bash
cd tools/agent
python export_lora_data.py            # 只统计：立即可用多少条、缺口多少
python export_lora_data.py --write    # 写出 lora_data/train.jsonl
python harvest_samples.py --dry       # 看还有多少"只有提问没回答"的存量
```

过滤规则（写在脚本里，别在别处再写一遍）：

- 只收 `issues` 为空的轮次（系统自己知道错了的不进训练集）
- 只收 2026-11-12 之后的日志（那之前的措辞是旧版本）
- 同一句问法出现多次 → **取最后一次**（修复后的回答才算数）
- 每条带 `_src`，将来能整批撤

### 4.2b 测试也算样本（`WB_SAMPLE_LOG=1`）

测试脚本直接调 `agent.run()`，**不经过 server，因此不会写 chat-*.log** ——
不额外接一条路，跑上千条测试也留不下一条样本。

```bash
cd tools/agent
WB_SAMPLE_LOG=1 python test_attack8.py     # 每轮落一行到 lora_data/auto-<日期>.jsonl
```

`export_lora_data.py` 会自动把它算进去（来源标 `auto:`），并剔掉
「换一台」「它呢」这类**脱离上文就没意义**的句子 —— auto 日志不保存上下文，
拿这种句子训练等于教模型答非所问。

实测（2026-11-13 跑完 15 个套件）：可用轮次 198，筛完剩 47 条自包含问答，
样本池从 58 条涨到 **98 条**。

### 4.3 采集"测试期"单独留档

如果想让一批测试同学的数据单独成集：

```bash
# 发链接时给统一前缀
https://xxx.trycloudflare.com/?k=码&u=test-w1-01
```

之后按 `uid` 前缀过滤日志即可（`grep '"uid":"test-w1-'`）。

## 五、组内成员怎么跑起来（不装大模型）

改代码不需要模型。两条路：

### 5.1 只改前端 / 内核（最常见）

```bash
git clone <repo>
cd tools/agent
python server.py            # 没 Ollama 也能起，页面顶部会显示"模型离线 · 按规则答"
```

离线时会降级成规则模板回答 —— 措辞短、追问答不了，但**排序、字段卡、审计逻辑全部照常**，
足够开发和自测。

### 5.2 想连维护者那台的模型

```bash
# 把模型地址指到维护者的机器（需要维护者开隧道或同局域网）
OLLAMA_URL=http://维护者IP:11434/api/chat MODEL=qwen3.5-4b python server.py
```

⚠️ Ollama 默认只监听本机。维护者要开 `OLLAMA_HOST=0.0.0.0 ollama serve` 才能被外部连，
而且**这等于把模型接口裸奔**，只建议在局域网 + 熟人之间这样做。

**更省事的做法**：组内成员直接连维护者的整套服务（方式 A/B），只在本地改代码时用离线模式。

## 六、故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面能开，但顶部显示"服务未响应" | 请求被 401 拦了 | 链接加上 `?k=访问码` |
| 第 2 个人提问特别慢 | 本机模型并发 1 | 正常，排队。别同时演示 |
| 链接突然 502/打不开 | 电脑睡眠 / 隧道进程被关 | 唤醒 + 重开 `cloudflared`（域名会变） |
| `cloudflared` 报 `failed to request quick Tunnel` | 网络被墙/代理干扰 | 换网络，或给 `cloudflared` 配 `HTTPS_PROXY` |
| 回答乱编 | 审计未必拦得住新说法 | 记下来，进 issue；别在演示时承诺"不会错" |
| 端口被占用 | 上一个进程没退 | `netstat -ano | findstr :7860` 后 `taskkill /F /PID` |

## 七、安全与隐私底线

1. **访问码不公开**：只发给要用的人；发现外泄就换一个码重启
2. **日志不外传**：测试同学的提问属于他们的数据，只用来筛样本，不入库、不公开
3. **不收集个人信息**：`uid` 是随机串，不记 IP、不记设备信息
4. **别开 `OLLAMA_HOST=0.0.0.0` 到公网**：Ollama 没有鉴权，等于把模型白送
5. **别把 `data/` 当真实报价**：快照是 2026-11-02，下单前必须自己核页面价
