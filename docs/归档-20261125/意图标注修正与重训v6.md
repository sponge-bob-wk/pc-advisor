> 已补 47 条种子数据，重训 v6。

## 一、问题

跑回归时 `test_intent` 有 2 项失败：

```
[FAIL] state_new_need → 不能是 ASK：我要一台游戏本      实际 state_range
[FAIL] state_new_need → 不能是 ASK：预算 6000 想买轻薄本  实际 state_range
```

**这不是环境问题**（单独跑也是 71/73），是模型的真实缺陷。

## 二、排查

### 2.1 确认是模型判断，不是规则

```python
il.route('我要一台游戏本', focus='zol-2103842')
# → intent=state_range, why=model:state_range
```

`why=model:` 说明是**模型判的**，规则没介入。

### 2.2 查训练集

```python
# 找「要/买 + 品类」的样本
想买轻薄本   → state_range
想买游戏本   → state_range
想买台式机   → state_range

共 3 条
```

**3 条全标成了 `state_range`。**

### 2.3 确认语义边界

| 说法 | test_intent 期望 | 训练集标注 | 冲突 |
|---|---|---|---|
| 我要一台游戏本 | `state_new_need` | `state_range` | ✅ 冲突 |
| 预算 6000 想买轻薄本 | `state_new_need` | — | — |

**用户确认：按测试的语义。**

```
「我要一台游戏本」  → state_new_need（主动索取 = 加条件）
「6000 的游戏本」    → state_range（纯描述范围）
```

**判据**：有「我要/想买/想要/买个/来一台/帮我找」等**主动索取动词** → `state_new_need`
纯描述价位/品类（无索取动词）→ `state_range`

### 3.2 修正源头文件的 3 条错误标注

**踩的坑**：我第一次直接改了 `route-train.jsonl`（产物），
但 `build_route_lora.py --write` 会从源头重新生成，**改动被覆盖了**。

```powershell
# 改产物 → 无效
route-train.jsonl 里的 想买游戏本 → state_new_need
# 重建后又被覆盖回 state_range
```

**正确做法**：改源头 `expanded-route.jsonl`。

```python
# lora_data/expanded-route.jsonl
想买轻薄本 → state_new_need  ✓
想买游戏本 → state_new_need  ✓
想买台式机 → state_new_need  ✓
```

**教训：修数据要改源头，不要改产物。**
产物是生成出来的，改了下次重建就没了。

## 六、教训

### 6.1 改数据要改源头

`build_route_lora.py` 从 `lora_data/*.jsonl` 汇总生成 `route-train.jsonl`。
**直接改产物会被下次重建覆盖。**

正确顺序：
```
改源头（expanded-route.jsonl / seed-*.jsonl）
  ↓
跑 build_route_lora.py --write
  ↓
验证 route-train.jsonl
```

### 6.2 测试期望和数据标注可能冲突

`test_intent.py` 写的是「我要一台游戏本 = state_new_need」，
但训练集标的是 `state_range`。

**这类冲突不报错，只是模型判错。** 如果没有测试，永远不会发现。

**这印证了项目的原则：判据只能有一处。**
测试和训练数据对同一件事有两种说法，一定会漂。

### 6.3 单个类别样本太少会被忽略

改前 `state_new_need` 96 条，听起来不少，但**「要+品类」这个具体模式只有 3 条**。

模型学到的是「品类词 → state_range」这个更常见的关联。

**补样本要补「具体模式」，不是补「类别总数」。**

## 七、给答辩的材料

### 7.1 「测试驱动发现数据缺陷」的案例

> 在回归测试中发现「我要一台游戏本」被误判为「范围描述」而非
> 「新需求」。经排查，根因是**训练数据中该模式的 3 条样本
> 均被错误标注**为 `state_range`，与测试期望的 `state_new_need`
> 相矛盾。模型忠实学习了训练数据的标注，因此产生系统性错误。
>
> 修正方式：（1）更正源头数据中的 3 条标注；
> （2）新增 47 条针对性样本（40 正例 + 10 负例），
> 覆盖「我要/想买/来一台/帮我找」等 10 余种句式变体；
> （3）重新训练，`state_new_need` 类别样本从 96 条增至 131 条。
>
> **这个案例说明：模型的行为缺陷往往源于数据质量问题，
> 而非模型能力不足。建立「测试 → 发现 → 溯源到数据 → 修正 → 重训」
> 的闭环，比单纯调整模型参数更有效。**

### 7.2 语义边界的定义方法

**两条规则的对比**：

| 说法 | 判据 | 意图 |
|---|---|---|
| 我要一台游戏本 | 有**主动索取动词**（我要/想买/来一台） | `state_new_need` |
| 6000 的游戏本 | 纯**描述**（价位+品类，无索取动作） | `state_range` |

**这个边界不是拍脑袋定的** —— 它对应系统行为：
- `state_new_need` → 加到已有条件里，重新推荐
- `state_range` → 重新开始一轮筛选

**如果判错，用户的新需求会被当成"补充说明"而丢掉。**
