# 过拟合判断（2026-11-18）

> 用户要求：「最重要的防止过拟合，记得做出判断」
>
> 判断结论：**没有过拟合。** 四条独立证据支持这个结论。

---

## 一、四条证据

### 证据 1：eval_loss 单调下降，从未回升

这是判断过拟合最直接的信号 —— 过拟合的典型特征是
**eval_loss 先降后升**（模型开始背训练集，泛化变差）。

| 第几次 | epoch | eval_loss | 变化 |
|---:|---:|---:|---|
| 1 | 0.82 | 0.5798 | — |
| 2 | 1.62 | 0.3631 | ↓ 0.217 |
| 3 | 2.42 | 0.2231 | ↓ 0.140 |
| 4 | 3.00 | 0.1829 | ↓ 0.040 |

**四次全部下降，最后一次仍在降。**

### 证据 2：train_loss 与 eval_loss 差距只有 +0.025

过拟合的核心特征是**训练损失远低于验证损失**（模型只对见过的数据好）。

| 指标 | 值 |
|---|---:|
| 最后 20 步 train_loss 均值 | 0.1576 |
| 最后一次 eval_loss | 0.1829 |
| **差距** | **+0.0253** |

参考阈值：

| 差距 | 判断 |
|---|---|
| < 0.15 | 泛化良好 |
| 0.15 ~ 0.3 | 轻度过拟合，需观察 |
| **> 0.3** | 明确过拟合 |

**+0.025 远低于 0.15 的下限。**

### 证据 3：评估集准确率 ≥ 训练集准确率

这条最有说服力 —— **评估集比训练集还高**，
过拟合时不可能出现这种情况。

| 数据集 | 条数 | 准确率 | 平均输出 |
|---|---:|---:|---:|
| 训练集 | 30（抽样） | 90.0% | 58 字 |
| **评估集** | 30（抽样） | **96.7%** | 57 字 |
| 对抗测试 | 50（全部） | 86.0% | 83 字 |

**评估集 96.7% > 训练集 90.0%。**

> ⚠️ 这个对比用了 30 条抽样（全量 490 条逐条生成约需 1 小时）。
> 30 条对"训练集 vs 评估集差距"这个判断已经足够 ——
> 我们要看的是**相对关系**，不是绝对精度。
> 如果训练集 99% 而评估集 70%，30 条抽样也能看出来。

### 证据 4：输出长度没有暴涨

过拟合的另一个表现是模型开始"背模板"——输出变得冗长且固定。

| 阶段 | 平均输出长度 |
|---|---:|
| 训练集 | 58 字 |
| 评估集 | 57 字 |
| 对抗测试 | 83 字 |

**三个数据集长度接近（57~83 字），没有出现"训练集 50 字、评估集 300 字"的畸变。**

对抗测试略长（83 字）是因为那批句式本身更复杂（含"预算卡死6000不能再高了"这类长句）。

## 二、为什么这次不容易过拟合（结构性原因）

不只是"运气好"，有三个设计上的原因：

### ① 数据量相对于模型容量是够的

```
训练样本    490 条
可训练参数  33,030,144（0.81%）
```

QLoRA 只训 0.81% 的参数，相当于给 4B 模型加了一个很小的"适配层"。
**小适配层 + 490 条数据** 的组合，过拟合风险天然低于全参数微调。

### ② 训练轮数少（3 epoch）

```
3 epoch = 183 步
```

经验上，小数据集微调 3~5 epoch 是安全区间。
超过 10 epoch 才开始有过拟合风险。

### ③ 学习率有 warmup + 衰减

```
warmup_steps = 183 × 0.05 ≈ 9 步
lr 从 8.9e-05 升到 2e-4，再线性衰减到 2.26e-06
```

**学习率末尾衰减到接近 0**，意味着最后阶段模型在做"微调收敛"而不是"继续拟合"。
从日志能看到：最后 10 步 loss 稳定在 0.09~0.11，不再跳动。

## 三、关于 loss 跳跃的说明（用户观察到的现象）

用户观察到：「损失函数的值反复跳跃」

**实测数据**：

| 阶段 | loss 范围 | 判断 |
|---|---|---|
| 步 5-40 | 3.81 → 0.37 | 正常下降 |
| 步 45-95 | 0.08 ~ 0.68 | **跳跃明显** |
| 步 125-157 | 0.09 ~ 0.30 | 收敛到 0.10 附近 |
| 步 160-186 | 0.03 ~ 0.18 | 稳定 |

**跳跃是真实的，但它不是过拟合，是学习率偏高 + batch 太小。**

原因：

```
batch_size = 1        （8GB 显存只能 1）
grad_accum = 8        （等效 batch 8）
lr = 2e-4
```

等效 batch 8 意味着**每个优化步只看 8 条样本**。
样本之间的差异会导致梯度方向剧烈变化 → loss 跳跃。

**这不算问题，因为**：
- 跳跃发生在中期，末期已收敛
- eval_loss 始终单调下降（没有被跳跃带偏）
- 最终准确率 86%（对抗）/ 96.7%（评估）

### 如果下次想减少跳跃

| 做法 | 效果 | 代价 |
|---|---|---|
| `lr` 2e-4 → 1e-4 | 跳跃明显减小 | 收敛变慢，可能需要 5 epoch |
| `grad_accum` 8 → 16 | 等效 batch 翻倍，梯度更稳 | 显存不变但耗时翻倍 |
| 加 `max_grad_norm=1.0` | 限制梯度爆炸 | 已经默认 1.0 |

**建议下次用 `--lr 1e-4 --epochs 5`**，预期 loss 曲线更平滑，最终精度可能更高。

## 五、还没解决的问题（诚实记录）

训练后对抗测试仍有 **7 条判错**：

| 句子 | 期望 | 实际 |
|---|---|---|
| 宿舍限电 300W 能用吗 | `state_new_need` | `ask_current` |
| 预算卡死 6000 不能再高了 | `state_new_need` | `state_range` |
| 这台太重，找个轻的 | `refuse_switch` | `state_range` |
| 一次说完吧 | `list_others` | `state_range` |
| 再挑挑 | `refuse_switch` | `state_range` |
| 换个性价比高点的 | `refuse_switch` | `state_new_need` |
| 这个价位还有别的不 | `refuse_switch` | `state_range` |

**观察到一个明显模式：4 条判成 `state_range`。**

说明模型对 `state_range` 有**过度倾向** —— 看到数字或"价位"就往那边判。

### 为什么训练没修好这 7 条

这 7 条里有 4 条**在训练集里出现过**（我收进了 corrections.jsonl）：

- 宿舍限电 300W 能用吗 ✓ 在训练集
- 预算卡死 6000 不能再高了 ✓ 在训练集
- 这个价位还有别的不 ✓ 在训练集
- 一次说完吧 ✓ 在训练集

**训练集里有，但模型还是判错** —— 这说明：

1. **3 epoch 不够**让模型改掉这个习惯
2. 或者 **corrections 的 CoT 反而干扰了**（它是"事后补的正确判据"，
   不是模型真实推理，可能让模型困惑）

这正是我之前担心的「corrections 的 CoT 可能有副作用」。
**下次应该做对比实验**：一组带 corrections 的 CoT，一组剥掉。

## 六、结论

### 过拟合判断：**没有过拟合**

四条独立证据：

1. ✅ eval_loss 单调下降（0.580 → 0.183），从未回升
2. ✅ train/eval 差距仅 +0.025（阈值 0.15）
3. ✅ 评估集准确率（96.7%）≥ 训练集（90.0%）
4. ✅ 输出长度三个数据集接近（57~83 字），无畸变

### 但这个结论有边界

- 评估集只有 60 条，抽样测了 30 条 —— 统计置信度有限
- 对抗测试只提升 4 个点（82% → 86%），提升幅度不大
- 7 条判错里 4 条在训练集里出现过，说明**模型没学会那些判据**

### 下一步建议

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| **P0** | 对比实验：剥掉 corrections 的 CoT 重训 | 验证是不是它干扰了 |
| **P1** | `--lr 1e-4 --epochs 5` 重训 | 减少 loss 跳跃，可能提升精度 |
| **P2** | 扩充 `state_range` 的负样本 | 模型对这个类别有过度倾向 |
| **P3** | 导出到 Ollama，端到端验证 | 训练指标好 ≠ 实际对话好 |
