# 训练日志规范（2026-11-18）

> 用户要求：「训练也要记录日志，这些都是后续毕设作品的一个量化标准，
> 包括写到简历上的项目」

---

## 1. 记录什么（三层）

### 第一层：原始日志（`train-*.log`）

训练脚本 stdout 的完整重定向。含：

- 模型加载进度、耗时
- 每 5 步的 loss / grad_norm / learning_rate
- 每次 eval 的 eval_loss / eval_runtime
- 训练结束的 `train_runtime` / `train_samples_per_second`
- 中断时的步数和已用时间

**用途**：排错、复现、追溯异常。

### 第二层：结构化记录（`lora_data/training_runs.jsonl`）

一次训练一条 JSON，字段见 §2。

**用途**：纵向对比（这次和上次比 loss 降了多少、eval 有没有变好）。

**自动写入**：`train_route_lora.py` 训练结束（含 Ctrl+C 中断）时自动调
`training_record.collect()` + `save()`。不靠人工记得跑。

### 第三层：成果页（`docs/训练成果与量化指标.md`）

把技术指标翻译成**简历/答辩能直接引用**的形式，含三个版本的简历描述。

**用途**：毕设报告、简历、面试讲述。

## 3. 怎么用

### ⚠️ 先分清终端：cmd 和 PowerShell 语法不同

用户踩过：在 **cmd.exe** 里敲 PowerShell 的命令会报错。

| 场景 | PowerShell | cmd.exe |
|---|---|---|
| 带空格路径 | `& 'E:\ai2026\Scripts\python.exe'` | `"E:\ai2026\Scripts\python.exe"` |
| 单引号 | ✅ 支持 | ❌ 不支持（只认双引号） |
| `&` 调用符 | ✅ | ❌ 报「此时不应有 &」 |

**cmd 里正确的写法**：

```cmd
cd /d E:\电脑涨价分析\tools\agent
chcp 65001
"E:\ai2026\Scripts\python.exe" watch_training.py --follow
```

`chcp 65001` 是为了让中文不乱码（cmd 默认 GBK）。

**PowerShell 里正确的写法**：

```powershell
cd E:\电脑涨价分析\tools\agent
& 'E:\ai2026\Scripts\python.exe' watch_training.py --follow
```

## 4. 中断时也记录

用户问：「如果噪声太大中间可以停吗」

**能停，而且停了也记录。** 三处改动：

### ① `save_steps` 从 100 降到 50

原来 183 步只在第 100 步存一次 —— 停在第 80 步就白跑（没有可用检查点）。
改成 50：会在 50/100/150 各存一次，任何时刻停都有最近的权重。

### ② 捕获 `KeyboardInterrupt`

```python
try:
    trainer.train()
except KeyboardInterrupt:
    interrupted = True
    print("已中断，当前第 %d 步，正在保存权重..." % trainer.state.global_step)
```

**不捕获的话，Ctrl+C 会让后面的 `save_pretrained` 根本不执行** —— 白跑。

### ③ 中断的记录标 `completed: false`

```json
{"completed": false, "interrupted_at_step": 120, "train_minutes": 18.5}
```

汇总表里会显示「中断@120」，不会和完整训练混淆。

### ④ 支持续训

```powershell
& $py train_route_lora.py --resume    # 从最新 checkpoint 接着跑
```

## 5. 判断「噪声太大该不该停」

训练 loss 有波动是正常的，看这三个信号：

| 信号 | 正常 | 该停 |
|---|---|---|
| `loss` 趋势 | 整体下降，波动 ±0.3 | 连续 30 步不降反升 |
| `grad_norm` | 0.5 ~ 5 | 持续 > 20（梯度爆炸） |
| `eval_loss` | 下降或平稳 | **连续 2 次上升**（过拟合） |

**最可靠的信号是 `eval_loss` 连续上升** —— 那说明模型在背训练集，
不是在学习。这时候停，用之前最好的 checkpoint。

### 怎么用最好的 checkpoint 而不是最后一个

`trainer_state.json` 里记了 `best_model_checkpoint`：

```json
{"best_metric": 0.912, "best_model_checkpoint": "lora_out/checkpoint-150"}
```

`training_record.py` 会把这个字段记下来。

## 6. 这些数字怎么进简历（提醒）

**不要只写"用了 LoRA 微调"** —— 那是人人都会写的。

要写**具体的、可核验的数字**：

| 别写 | 要写 |
|---|---|
| 用了 LoRA 微调模型 | QLoRA 4bit，只训 0.81% 参数（33M/4B） |
| 训练了一个对话模型 | 533 条路由层训练集，28% 带思维链，8GB 显存 28 分钟 |
| 做了数据清洗 | 补齐 25 个字段维度，发现 7 台机器重量记成 1000kg |
| 写了测试 | 647 条自动化测试，其中 144 条专门验证判据分辨力 |
| 保证不编造 | 22 条出口审计判据覆盖 4 条输出路径，配套判据矩阵静态分析 |

**数字要能被追问。** 如果面试官问"0.81% 怎么算的"，
你要能说出 `33,030,144 / 4,055,498,240`。

这就是为什么记录要结构化 —— 随时能查。
