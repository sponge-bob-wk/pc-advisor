# 分析上下文：让追问接得住指代（2026-11-22）

> 用户问完「各品牌数量对比」，接着问「那它平均价格多少」——
> 系统给了**全库平均**，而不是刚才那个品牌的平均。

---

## 一、问题

实测（2026-11-22）：

`
Q1: 各品牌数量对比
    → 按品牌分了 16 组，最大组 联想（98 台）

Q2: 那它平均价格多少
    解析 → {"agg":"mean","field":"price","filter":{}}
    结果 → 平均 ¥11,360（样本 223 台）    ← 全库平均

    期望 → 联想平均 ¥13,206（98 台）      ← 差 2000 元
`

**用户以为是联想的，系统给了全库的。**

这比不回答更危险：数字是真的（确实是全库平均），
但答的不是问的问题，而且用户看不出来。

---

## 二、根因

nalyze.parse_query() 只看当前句，不知道上一轮在分析什么。
「它」「这个」「那 XX 呢」这些指代词在孤立解析时必然丢信息。

---

## 三、解法：给解析器喂上下文

新增 nalyze_ctx.py，维护上一轮分析的关键信息：

`python
{
  "agg": "groupby",
  "group_by": "brand",
  "top_group": "联想",     # 最大的一组
  "n": 223,
  "rows": [...]            # 排行前 3 名
}
`

parse_query(text, ctx=...) 把上下文压成一句话喂给模型：

`
【上一轮的分析】上一轮是按「品牌」分组对比；其中最大的一组是「联想」；样本 223 台
如果用户这句话用了指代（它/这个/那 XX 呢），
就按上一轮的对象去理解，并把对应的筛选条件写进 filter。
`

模型据此解析出 {"filter": {"brand": "联想"}}。

### 为什么不全靠模型

模型有时会忽略上下文（实测「它的平均价格呢」→ ilter={}）。

所以加一层**代码兜底**：

`python
if ctx and not flt.get("brand"):
    if analyze_ctx.has_reference(text) and ctx.get("top_group"):
        flt["brand"] = ctx["top_group"]
`

判据：有指代词 + 解析结果没有品牌筛选 + 上一轮有最大组 → 补上。

### 为什么不写规则硬编码「它=最大组」

「它」可能指上一句提到的任何东西（最大组 / 某个机型 / 某个品牌）。
规则穷举不完 —— 这正是「模型理解、代码兜底」的适用场景。

---

## 四、顺带修的品牌名不统一

查上下文 bug 时发现：rand 有 19 种值，其中 联想 和 联想来酷 是两组。

**两个后果**：

| 问题 | 表现 |
|---|---|
| 分组重复计数 | 「各品牌对比」里联想被拆成两组 |
| 筛选口径不一致 | _apply_filter 用子串匹配（'联想' in brand），会匹配到 联想来酷；但 groupby 按原值分组 |

实测数字：
- 精确匹配 rand=='联想' → 98 台，平均 ¥13,206
- 子串匹配 '联想' in brand → 100 台，平均 ¥13,070

**差 2 台、136 元 —— 用户不会发现，但这就是「同一件事两个答案」。**

新增 
ormalize_brand.py，把子品牌归入主品牌：

| 子品牌 | 主品牌 |
|---|---|
| 联想来酷 | 联想 |
| Lecoo | 联想 |
| ThinkPad / 拯救者 / 小新 | 联想 |
| Redmi / RedmiBook | 红米 |
| MagicBook | 荣耀 |
| MateBook | 华为 |
| Surface | 微软 |

**归并原则：只归并有明确归属关系的，不确定的不动** ——
宁可多一组，也不要错并。

修复后：品牌 19→18 种，精确匹配 100 台 = 子串匹配 100 台 ✓

## 五、测试

	est_analyze.py 加第 9 组（4 个断言）：

`
[9] 分析上下文：指代消解（调模型）
  [OK ] 第 1 轮记住最大组 = 联想
  [OK ] 第 2 轮解析带上了品牌筛选
  [OK ] 第 2 轮只算 联想（100 台），不是全库
  [OK ] 不带上下文时 filter 为空（对照）
`

**最后一条是「反向对照」** —— 确认不是所有句子都被硬塞品牌，
而是只有带指代的才补。没有这个对照，可能「修好了 A 却弄坏了 B」。

## 七、还能怎么改（P2 后续）

### 7.1 上下文只在「同一轮对话内」有效

现在 _LAST_ANALYSIS 是模块级变量，用户换话题后不会清空。
可能出现「问完品牌对比，聊了半天机型，突然问『那它呢』，
系统还按品牌对比的上下文理解」。

**应该**：检测话题切换时清空（比如 ocus 变了、或连续 N 轮不是分析）。

### 7.2 多轮分析的链条

`
Q1: 各品牌对比
Q2: 那它平均价格多少        ← 现在支持
Q3: 那最贵的那台叫什么      ← 需要「上一轮结果里的极值」
`

Q3 需要上下文里带「上一轮算出的极值对应哪台」，现在没有。

### 7.3 分析结果的可视化

「价格分布」现在只有文字（5 个区间 + 台数）。
如果生成内联 SVG 柱状图，答辩演示效果好很多。
