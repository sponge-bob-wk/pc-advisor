## 最重要的三个发现

### ① 规则层曾经是负价值

v7 刚训完时，测出来：

```
模型裸准确率  86.0%
规则否决后    72.7%   ← 规则改坏 21 条，救回 1 条
```

**12 条是同一个原因**：`_HARD_ANCHOR` 里混进了「屏幕」「续航」「打游戏」
这些**用途词和属性名词**，配上"没有祈使动词 = 不是在提要求"的假设
（中文里不成立），于是：

```
「主要是打游戏」→ 判成"在问当前这台" ✗
「续航要长」    → 同上 ✗
```

还有一个更隐蔽的：**同一判据写了两遍**。
`analyze` 的统计动作判断在 `model_route()` 和 `classify()` 各写一份正则，
改一处漏一处，导致「最便宜的是哪台」被第二处否决回 `state_range`。

### ② 数据层的污染必须回数据层修

v7 有个奇怪现象：模型对「打游戏」「写代码」输出

```json
{"intent": "fit", "topic": "none", "fit": true}
```

`intent` 被填成了 `"fit"`。查下来是训练数据里
「预算 5000，写代码 → fit:true」这种错配 —— `fit` 只在
`intent=ask_current` 时才有意义。

**打规则补丁治不好，必须修数据重训。** v8 修完后 4 条错误自然消失。

### ③ 老模型补丁会变成新模型的负担

诊断发现 4 条规则**全是为 v5/v6 的错误写的**，注释里写着
「模型判 refuse_switch」——但 v8 已经判对了，补丁反而起了反作用。

最典型的是这条：

```python
# 「还有别的吗」「能看看别的吗」→ 规则判 list_others
```

老模型判 `refuse_switch` 时，当时的交互是"只推 1 台"，
所以打补丁改成列清单。但 v8 判 `refuse_switch` 是对的，
产品行为也是"换一台推"。**已删除该条**。

## 两次「以为是 bug，其实是标注错」

### ① 「最便宜的是哪台」→ `state_range`

SYS_TMPL 里写着「哪个最便宜 → state_range（是找一台机器，不是统计）」，
但训练数据里 30+ 条这类句子全标 `analyze`，而且
`analyze.py` L267-279 明确支持 `agg=top/bottom`。

**提示词和训练数据自相矛盾**，这才是准确率上不去的隐藏原因之一。
已修正提示词。

### ② 「有没有机械革命的」→ `ask_current`

我的对抗测试集标 `ask_current`（问当前这台细节），但查代码确认：

```python
if _sw_lab == INTENT_REFUSE_SWITCH:
    want_switch = True    # ← 会换一台
```

用户已经看到一台联想，问"有没有机械革命的" = 要看另一个牌子
= **换台**。所以模型判 `refuse_switch` 是对的，**测试集标错了**。

修正了 4 条标注。

> ⚠️ 这两条修正会让准确率"看起来"上升，但属于**修正测量误差**，
> 不是真实能力提升。归档里要区分清楚。


**共同模式：有依赖关系的步骤，顺序反了就白做。**

### 检查了，但检查错了对象

```
① 'sessions.js' in html         → 匹配到注释里的文字，实际 script 标签没加
② core.load()["offers"] (34条)  → 拿去查"库外机型"，但实际池子是 pool_offers() (223台)
③ _has_stat 写了两份             → 改一处漏一处
```

**共同模式：验证要看实际产物，不是看自己写的检查逻辑。**

### Python heredoc 会吃掉引号

用 PowerShell 的 `@"..."@` 传 Python 脚本时，`r"..."` 里的双引号会被吃掉，
导致语法错误。**这类脚本要写成 .py 文件再执行**，不要走 heredoc。
