# 最近电脑和手机涨价了吗

一个单文件网页工具：输入想买的东西和预算，看清涨了多少、哪台最值、优缺点在哪、国补能省多少、该不该现在买。

- **打开方式**：双击 `电脑涨价趋势.html`。手机上传过去用浏览器打开也一样。
- **不联网、不登录、不上传**。价格数据已经固化在文件里，断网照常显示。
- **结果只存在本机**（localStorage），换设备、换浏览器看不到上次的。

## 三步

1. 打开 —— 光标已经在输入框里
2. 输入 —— 打字，或点下面的快捷标签
3. 看结论 —— 结论 → **按你的侧重排出的榜单（带优缺点）** → 国补怎么算 → 品牌 → 设计缺陷 → 涨价详情（可展开）

## 覆盖范围

5 个品类、34 台具体机型、38 条公开来源、21 个品牌。

| 品类 | 机型数 | 维度 |
|---|---|---|
| 轻薄本 | 10 | 价格 / 性能 / 可加装 / 品牌 / 便携 |
| 游戏本 | 6 | 同上 |
| 台式整机 | 2 | 同上 |
| 升级内存硬盘 | 4 | 同上 |
| 手机 | 12 | 价格 / 性能 / **续航** / **影像** / 品牌 |

**手机和电脑不用同一套维度。** 手机的内存和存储全都不可换，「可加装」这个维度对手机没有意义；
「便携」在手机上也没有区分度（都在 180~220g）。硬套同一套维度会让手机排序整体失真。

## 排序怎么算

榜单不是「按价格从低到高」，而是**按你的侧重加权**。权重在 `data/prices.json` 的 `weights` 里。

**电脑（4 种侧重）**

| 侧重 | 价格 | 性能 | 可加装 | 品牌 | 便携 |
|---|---|---|---|---|---|
| 省钱优先 | 40% | 25% | 20% | 10% | 5% |
| 性能优先 | 15% | 50% | 15% | 10% | 10% |
| 能加装优先 | 18% | 17% | 45% | 15% | 5% |
| 要带出门 | 22% | 18% | 10% | 15% | 35% |

**手机（4 种侧重）**

| 侧重 | 价格 | 性能 | 续航 | 影像 | 品牌 |
|---|---|---|---|---|---|
| 省钱优先 | 40% | 25% | 15% | 10% | 10% |
| 性能优先 | 15% | 50% | 15% | 10% | 10% |
| 续航优先 | 20% | 15% | 45% | 10% | 10% |
| 拍照优先 | 15% | 15% | 10% | 50% | 10% |

五个维度都归一到 0–100 再加权：

- **价格分**：同品类池内相对位置（便宜=高分）。给了预算就叠加预算约束 —— 有余量加分，超预算掉得很快。
- **性能 / 续航 / 影像**：**都必须在池内归一**。这是踩过两次的同一个坑：原始分差只有几分，而价格分是池内归一的（跨度能到 70 分），权重再高也拉不开差距 ——「续航优先」会变成摆设。
- **品牌分**：售后网点密度 × 二手保值，映射到 60–100。**不能直接 ×10 映射到 0–100** ——
  原始分差 1 分就变成 10 分，足以压过「续航/影像」的真实差距。压到 60–100 后既不忽略品牌，也不让它喧宾夺主。
- **可加装**：留插槽 100 / 看 SKU 60 / 焊死 25。
- **便携**：很轻 100 / 正常 70 / 较重 40 / 不适合携带 10。

### 但加权只是第二层：主维度是硬门槛

纯加权有一个治不好的毛病 —— **主维度靠「拉票」赢不了**。用户点「性能优先」，性能权重已经 50%，
可品牌和续航的票加起来仍然能把性能低一档的机器顶上去。这不是权重没调好，是加权平均这个模型表达不了
「性能是硬门槛」这句话。

所以每个侧重里多了一个 `primary` 字段。排序按这个顺序逐级比较：

```
① 超预算的排最后
② 主维度档位（池内跨度三等分，0/1/2）
③ 同档内，主维度原始分从高到低
④ 主维度打平，才看加权总分
⑤ id 兜底，保证排序稳定可复现
```

| 侧重 | primary | 说明 |
|---|---|---|
| 省钱优先 | **null** | 它本来就是综合权衡，没有单项硬门槛，走纯加权 |
| 性能优先 | perf | |
| 能加装优先 | upgrade | |
| 要带出门 | portable | |
| 续航优先 | battery | |
| 拍照优先 | camera | |

**为什么是「分三档」而不是连续值**：连续值做硬门槛会把「差 1 分」也当成断层，
那又回到加权的老毛病，只是换了个方向。差一档才算「明显不如」。

### 榜单上那个数字

榜单右侧的大数字**就是排序真正依据的那个数**，而且尽量用原始值：

| 侧重 | 显示 | 例 |
|---|---|---|
| 性能优先（手机） | 换算后的性能分 | 小米 17 Ultra「90分」 |
| 性能优先（电脑） | 池内归一位 | Redmi Book Pro 14「100分」 |
| 续航优先 | 真实容量 | 荣耀 Power2「10,080mAh」 |
| 拍照优先 | 影像主观分 | 小米 17 Ultra「95分」 |
| 可加装 / 便携 | 档位原文 | 「留插槽」「很轻」 |
| 省钱优先 | 加权综合分 | 红米 K90「86」 |

**不显示池内归一值的原因**：归一值会把真实差距放大。影像 90 和 88 只差 2 分，归一会变成 95 和 92，
读者以为是两个档次的差距。原始值能和详情页、和参数表对上。

早先这里显示加权总分，在分档排序下会出现「第 2 名 73 分、第 3 名 74 分」——
排序是对的，但读者只会认为这是 bug。测试里有一条 `榜单显示分数不倒退` 专门锁这个。

### 性能分怎么来的（手机）

**不是凭印象打分，而是用 Geekbench 6 实测换算**：

```
性能分 = 100 ×（0.5 × 单核 / 4000 + 0.5 × 多核 / 12000）
```

4000 / 12000 是当前一代旗舰的上限锚点（A19 单核、骁龙 8 Elite Gen5 多核）。单核管「打开 App、滑动」，
多核管「多任务、渲染、导出」，各占一半。每台机型在 `prices.json` 里都存了 `chip` 和 `gb6: [单核, 多核]`，
`build.py` 会校验 `perf` 能否由 `gb6` 推出来 —— 手改其中一个而不改另一个，构建直接失败。

| 机型 | 芯片 | GB6 单/多核 | 性能分 |
|---|---|---|---|
| 小米 17 Ultra | 骁龙 8 Elite Gen5 | 3569 / 10956 | 90 |
| 红米 K90 | 骁龙 8 Elite | 3300 / 11000 | 87 |
| iPhone 17 | A19 | 3730 / 9470 | 86 |
| 荣耀 Magic8 Pro Air / vivo X300 | 天玑 9500 | 3142 / 9650 | 79 |
| iQOO Z11 Turbo / 真我 Neo8 / 摩托 X70 Air Pro | 骁龙 8 Gen5 | 2864 / 9568 | 76 |
| 一加 Turbo6 | 骁龙 8s Gen4 | 2080 / 6581 | 53 |
| 荣耀 Power2 | 天玑 8500 Elite | 1712 / 6489 | 48 |
| 华为 Mate80 | 麒麟 9030 | 1866 / 6000 | 48 |
| OPPO Reno16 | 天玑 8550 SUPER | 1560 / 5733 | 43 |

**续航项直接存额定容量 mAh**（10080 ~ 3692），不换算成虚构的 0–100。容量能从官网核实，分数不能。
影像分仍是主观综合（传感器尺寸、长焦规格、实测样张口碑），这一项在页面上明确标了「主观分」。

### 性能分怎么来的（电脑）

同一套逻辑，换一把尺子 —— **Cinebench R23 实测换算**：

```
性能分 = 100 ×（0.5 × 单核 / 2400 + 0.5 × 多核 / 40000）
```

2400 / 40000 是当季消费级上限（14900KS / 9955HX 级）。**两把尺子的锚点都取旗舰上限，
所以手机 48 分和电脑 50 分放同一张表里可比，都表示「约为旗舰的一半」。**

每台电脑在 `prices.json` 里存了 `chip` 和 `cb23: [单核, 多核]`，`build.py` 校验 `perf` 能否由 `cb23` 推出，
差超过 1 分直接构建失败。**顺手查出来的三个真实错误**：

| 问题 | 改造前 | 改造后 |
|---|---|---|
| 酷睿5 320（6C/6T，R23 多核 7540）与 R7 H255（8C/16T，15475）同分 | 都是 28 | 50 vs 62 |
| 同款 Ultra 7 251HX 在不同机型上两个分数 | 隐星 48 / 耀世 52 | 三台统一 77 |
| 10 台电脑 spec 里连 CPU 型号都没写 | 「16G + 512G」 | 补上 R7 H255 / Ultra 5 226V |

| 机型 | 芯片 | R23 单/多核 | 性能分 |
|---|---|---|---|
| 机械革命 苍龙 18 Pro | R9-9955HX | 2157 / 39019 | 94 |
| 暗影精灵 Pro 15 | Ultra 7 255HX | 2027 / 29012 | 78 |
| 隐星 P16 Pro / 极光 X / 耀世 18 Pro | Ultra 7 251HX | 2096 / 26476 | 77 |
| DIY 整机 i5-14600KF | i5-14600KF | 2097 / 24683 | 75 |
| 只换板 U：9800X3D | R7 9800X3D | 2095 / 23163 | 73 |
| Redmi Book Pro 14 | Ultra 5 338H | 2002 / 15988 | 62 |
| 戴尔灵越 15 2026 | Ultra 5 225H | 1985 / 16436 | 62 |
| 无界 14X / 战 66 八代 / 小新 16 | R7 H255 | 2055 / 15475 | 62 |
| 天选 7 | R7 H260 | 1760 / 15321 | 56 |
| 小新 Air15 2026 / 荣耀 X14 | 酷睿5 320 | 1939 / 7540 | 50 |
| 华硕无畏 16SE 2026 | 酷睿5 320 | 1928 / 7880 | 50 |
| 小新 Air14 柔光版 | Ultra 5 226V | 1746 / 9041 | 48 |
| MateBook D16 | i5-13420H | 1690 / 7839 | 45 |
| 内存条 / 固态 | 不涉及 CPU | — | 不涉及 |

**同款 CPU 同分的平局是事实，不是精度丢失**：R7 H255 / Ultra 5 225H / Ultra 5 338H 的 R23 多核都在
15500~16400 区间，换算后就是同一个分数。测试因此只验「头名性能分 == 池内最高」，
而不是「头名必须是某台特定机器」。

**内存条和固态没有 CPU，性能项存 `null`，不编分数。** 若当 0 分算，等于「因为不涉及所以判它最差」。
正确做法是 `score()` 把它从权重里摘掉，剩余权重按比例放大回 1（记录在 `wsum` 里），榜单显示「不涉及」。

**预算容差 5%**：说「5000 以内」时，5009 那台不会被踢掉，只标「略超 ¥9」。差 9 块钱就换一台机器，不是用户想要的决策方式。

切换侧重时如果当前侧重在新品类里不存在（电脑的「能加装」切到手机上），会自动退回该品类的第一个侧重，不会排出空榜单。

## 国补：电脑和手机不是一套规则

这是最容易让人白亏的一块，所以单独立块，带实时计算。

| | 电脑 | 手机 |
|---|---|---|
| 归哪一类 | **家电类** | **数码类** |
| 补贴比例 | 15% | 15% |
| 单件封顶 | **1500 元** | **500 元** |
| 价格门槛 | **无** | **≤ 6000 元，超了不补** |
| 吃满要实付 | 10000 元 | 3333 元 |

计算器输入一个价格，同时算出「买电脑能补多少」和「买手机能补多少」，并说明卡在哪。
**5999 和 6001 差的不是 2 块钱，是 500 块** —— 这是今年最大的单一差价。

用手机的 6000 红线去套电脑，是最常见的白亏：一万五的笔记本照样能拿满 1500。

## 优缺点与设计缺陷

**每个机型都有 `pros` 和 `cons` 两个字段，构建时强制校验，缺一个就构建失败。**
只夸不贬的推荐不算推荐 —— 这是需求里明确的一条。

榜单前 3 名直接显示「2 条优点 + 1 条缺点」速览，点进详情看完整两栏。

**电脑另有一块「设计缺陷」**，因为涨价是一次性多花钱，设计缺陷是三年里反复折磨你，而价格能比、缺陷不能退货：

| 缺陷 | 症状 | 涉及 |
|---|---|---|
| 低温锡虚焊 | 开机正常，用一会儿花屏/死机，冷机又能开 | 小新 Pro13 ARE、小新 Air15 锐龙版、天选系列 |
| 显卡供电烧毁 | 高负载后黑屏、显卡无法识别、反复重启 | 神舟战神 T9 等公模游戏本 |
| 屏轴 / 屏幕泛白 | 单手开合屏晃、右下角泛白、HDR 色阶断裂 | 公模游戏本、ThinkBook 14+ |
| 早期驱动卡死 | 开俩 Word 卡死、0x10E 黑屏、外接盘掉盘 | ThinkBook 14+ 2026 等首发新平台 |
| 充电协议挑食 | 手上的 100W 充电头插上没反应 | ThinkBook 14+ 2026（需 >60W PD） |
| 专有内存模组 | 以为有插槽，实际是 LPCAMM2 | ThinkPad T14p 2026、T14 Gen7 |

手机没有这一块 —— 手机的设计问题主要是影像/续航/散热的取向差异，已经在优缺点里说清了。
手机有的是另一组坑：大存储溢价、6000 门槛、等下轮降价。

## 结论是怎么来的

**不靠模型自由发挥，靠一张人写的规则表。**

输入 → 匹配品类（关键词表）→ 取出该品类的涨幅、原因、建议 → 套规则表 → 输出。
同一个输入永远得到同一个结论。改 `data/prices.json` 就能改结论：

- `categories[].headline / reasons / action / budgetBands` —— 结论句（手机有自己的预算档）
- `categories[].keywords` —— 识别范围
- `dimensions` / `weights` —— 按品类分维度、分权重
- `offers[]` —— 榜单据池（价格、性能、续航/影像、`pros`/`cons`、`caution`、来源）
- `brands[]` —— 品牌表，带 `scope: pc|phone`（同名品牌可以两处都登记）
- `subsidyRules` —— 国补两套规则
- `defects` —— 电脑设计缺陷表
- `trapsByKind` —— 按大类的坑

**关键词冲突已处理**：品牌词（小米/华为/荣耀/苹果）同时是手机品类的关键词，
所以「小米笔记本」会先判定为电脑硬件再匹配品类，不会被判成手机；说了「笔记本」但没说是哪一类，按轻薄本处理。

## 数据从哪来

**38 条公开报道，34 个具体机型，21 个品牌**。逐条记了标题、媒体、日期、原文链接，页脚可展开核对。
每条结论下面都标「依据：某某（日期）」，能追到具体是哪一篇。

问 Mac 会明确说「这条线我暂时没有可靠数据」，不给看起来像样的假数字
（MacBook Air M5 这轮定价没变，它的调价逻辑和 Windows 阵营不一样，硬套会误导）。
宏碁在品牌表里但标了「未进榜单」—— 没找到能核实的在售到手价，宁可不排。

**口径冲突时给区间，不取单一值。** 同一台小新 Pro14，不同报道有 4138→6557、4000 出头→6500、
优惠前标价 7799 三种说法，页面统一按「实际成交价」口径取值，并在文案里说明。

**价格全是国补后到手价**，这是目前价格最大的单一变量 —— 补贴退出后同款回升约 15%，页面里写明了。

## 关键发现

**电脑：2026 年买电脑的核心变量不是价格，是内存焊没焊死。**

内存涨了 5 倍，「先买 16G、以后再加」这条老路断了。所以工具把「能不能加内存」做成一等公民：

- 判断规则：规格页搜「内存」，写 **LPDDR5 / LPDDR5X** 就是焊死，写 **DDR5 SO-DIMM** 才有插槽。这一条能筛掉九成误判。
- 板载机按「三四年后还想同时开几个重应用」倒推容量，别按今天的用量买。
- 同一个品牌里 E14 能加、X1C 不能 —— **别按品牌判断，按型号判断**。

**手机：核心变量是「有没有卡进 6000」。**

存储占手机成本从 10%~15% 飙到 30%~40%，旗舰机 30%~60% —— 第一次超过处理器成为最贵的零件。
12GB+256GB 组合的采购价从 500 涨到 2200。而国补对手机是硬门槛：超 6000 一分不补。
所以手机选购的第一件事不是看配置，是看价签有没有跨过那条线。

## 怎么更新数据

```bash
python tools/refresh.py          # 体检：哪些来源超过 45 天没核对、该看哪个链接
python tools/build.py            # 改完 prices.json 后重建
node tools/test.js               # 438 项自测
```

`refresh.py` **不会自动抓网页**。这几个来源的页面结构各不相同、随时会改，自动抓要么抓空、
要么抓到旧值 —— 而「数字看着对、其实是错的」是这工具最不能出的错。所以走「体检 + 人工改数 + 构建校验」。

`build.py` 会拦下这些情况（任何一条不过就构建失败）：

- 「去年 → 现在」的涨幅和 `change` 字段对不上（容差 2%）
- 机型引用的品牌不存在、品牌跨大类串了（手机品牌挂电脑机型）
- 每个品类必须至少有一台机型
- 机型缺 `pros` 或 `cons`、优缺点里有空条目
- 手机机型带了 `upgrade`/`portable`（这两个字段对手机无意义）
- 手机超 6000 但 `caution` 里没提醒补贴全无
- 权重和不为 1、权重用了该品类没有的维度、`primary` 不是该品类已有维度
- 手机缺 `chip` / `gb6`，或 `perf` 与 GB6 换算结果对不上
- 同一侧重的 `primary` 声明缺失（`value` 侧重必须是 null）
- 国补 `saturate`（吃满点）和 `rate`/`cap` 推不出来
- 电脑 `threshold` 不是 null（它归家电类，没有价格门槛）
- 预算档不是递增

数据是老工具唯一的失效方式，所以宁可麻烦一步，也不让它悄悄变旧。
