## 二、修掉的 3 个问题

### 问题 1：「要台式」没问预算就出方案

**现象**：用户只说「要台式」，系统直接出了 2 套方案（2695 字），
默认标签是「主流游戏」「高端全能」。

**根因**：`agent.py` L6918 的 `else` 分支——没预算时把**所有 TIERS 都生成一遍**。
用户可能想 3000 办公机，也可能想 3 万工作站，不知道预算就出方案等于蒙。

**对比**：「想买个笔记本」→ clarify 问用途和预算（20 字，干净）。

**修法**：
```
没预算 + 没用途 → 追问「预算多少、主要干什么」
没预算 + 有用途 → 追问「还差预算，大概多少」
有预算          → 正常出多方案对比（原能力保留）
```

修复后：
```
要台式              → clarify「预算多少、主要干什么」✓
要台式，打游戏       → clarify「知道了用途，还差预算」  ✓
台式机，预算8000，打游戏 → build_pc，3 个方案          ✓
```

### 问题 2：同预算跨品类性能差距没提示

**现象**：「预算10000 剪视频」推 MateBook 14（¥6299, perf=67），
但同价位游戏本 perf 能到 94 —— 用户损失 30% 性能而不自知。

**数据（代码算的）**：
```
10000 预算性能天花板：
  轻薄本  perf=67   ¥6299  MateBook 14 2026
  游戏本  perf=94   ¥10899 苍龙 18 Pro
  游戏本  perf=81   ¥9999  惠普暗影精灵11
```

**为什么不直接换品类**：用户说「要笔记本」可能真的不想要厚重的游戏本，
替用户做决定是错的（和之前 `upgrade` 那个问题同类）。

**修法**：新增 `_crosscat_value_hint()` —— **推荐不变，把权衡摆出来**：

> 同预算下游戏本更强：惠普暗影精灵11（¥9999，性能高约 21%，但重量约 2.4kg）。你现在这台更适合携带。

**触发条件**（三条同时成立，避免噪音）：
1. 异品类同价位 perf 高 ≥15%
2. 用户没明确说要轻/便携
3. 异品类确实有货

**为什么不会被 `_cross_cat` 拦**：那条规则拦的是**模型凭空说**
（内核没取台式机数据却说"台式机能给你"），而这里是代码算的真实数据。

### 问题 3：`test_weight` W8 规则被我破坏

新增函数里写了 `best.get("weightKg")`，触发 W8「出口层不许裸读 weightKg」。

这条规则是保护性的——历史上「core 改好了但出口层忘了改」的判据漂移**复现过 9 次**。

**修法**：改用 `core.effective_weight(o)`（统一取值，含 weightKg 字段 + pros/cons 文本两个源）。

```

不是 `/notebook/{id}.shtml` —— 之前所有匹配逻辑都找错了对象。

```
