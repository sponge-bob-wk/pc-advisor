## 一、多轮对话审计：产品是好的，是我的测试错了

### 第一版审计结论：完全错误

我写了 6 个多轮场景，结果显示**每步都在重新问"是笔记本还是台式"**，
看起来像"上下文完全丢失"的严重故障。

### 真正原因

**服务端无状态**，`known` 由客户端每轮回传。我的脚本只发了 `{text, uid}`。

前端 `app.js` L992-998 实际是这样的：
```javascript
body:JSON.stringify({
  text:text, known:S.slots, asked:S.asked,
  last_stage:S.lastStage, seen:S.seen, focus:S.focus
})
```

而且返回时读的是 `d.slots`（不是 `d.known`），并用 `mergeSlots()` 合并。

## 二、修掉的问题：31 组同名机型

### 问题

审计时发现「机械革命 无界15X Pro 锐龙7 H 255」被替换成了
`机械革命[无界15X Pro](jd链接)` —— 链接指向了**短名的那台**，串机器了。

深挖发现池子里有 31 组同名机型：

```
「联想拯救者」×16      每台配置价格都不同，但名字一样
「ThinkPad」×9
「惠普暗影精灵11」×5
「ROG 枪神9 Plus Ultra」×5
「华硕天选6 Pro 酷睿版」×3
...
```

### 根因

ZOL 抓取时 `name` 只拿到品牌/系列，丢了型号全名：
```json
{"name": "联想拯救者", "cpu": "i5 12500H", "gpu": "RTX3050",
 "ram": 16, "screen": 15.6, "list": 7399}
```

配置字段都有值，只有名字不完整。

### 后果（两条都影响用户）

1. **用户看不出区别**：¥7399 的 i5-12500H 和 ¥9799 的 i7-14700HX 都叫"联想拯救者"
2. **链接串机器**：`_linkify_models` 按名字匹配，同名多台时只取第一台

### 修法

**只在同名组内**，用配置字段补后缀：
```
「联想拯救者」→「联想拯救者（i5-12500H/16G/RTX3050/15.6"）」
```

规则：
- 只改同名的（唯一的那些名字够用，加后缀反而啰嗦）
- 已有括号配置的不动（如「小新 Pro 14 2026（锐龙版）」）
- 配置完全相同但不同渠道的，加渠道+价格区分

### 结果

```
完全同名：31 组 → 0 组
改了 99 台
```

抽样（原 16 台「联想拯救者」）：
```
联想拯救者（i5-12500H/16G/RTX3050/15.6"）      ¥7399
联想拯救者（R5-4600H/16G/GTX1650/15.6"）       ¥5600
联想拯救者（i7-14700HX/32G/RTX4060/16.0"）     ¥9799
联想拯救者（i9-14900HX/32G/RTX4090/16.0"）     ¥25399
```

## 三、一个好消息：假警报

改完名跑回归时，我的汇总脚本显示：
```
test_neg     143/144   ← 退化
test_intent  71/73     ← 退化
```

单独跑这两个文件，**实际都是全绿**（144/144、73/73）。

原因是我的正则只匹配「通过 N / M」，而 `test_neg` 输出的是
「判据分辨力 144/144」，`test_intent` 的中间某个 FAIL 字样被误抓。

**教训**：汇总脚本的正则要覆盖所有输出格式，否则会误报退化。
