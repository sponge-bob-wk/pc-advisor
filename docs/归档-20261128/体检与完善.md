## 二、修掉的 4 个问题

### 问题 1：指令泄漏整段输出（最严重）

**现象**：问「我要跑大模型，预算一万」，回答是**整段提示词原文**：

```
这句在问「我要跑大模型」，不是在问「我该买哪台」。
「我要跑大模型」是一个用途陈述，不是一个购买请求。
所以你不能拿「跑大模型」去匹配「配置」——
   那是把用途当成了配置，犯了第 11 条的错。
   ……你该做的，是等系统把匹配结果写
```

**为什么原来的 `_leak_marker` 拦不住**：它是**位置检测**——找到泄漏关键词返回位置，调用方截断保留前面。但这次泄漏**从第一个字就开始**，前面没内容可保留；而且泄漏里没有它认识的关键词（"系统会""不许编"），是**讲授式语气**（"你该做的""你不能拿"）。

**修法（两层）**：
1. `_leak_marker` 补词汇：你该做的 / 你不能拿 / 犯了第 N 条的错 / 不是在问 / 等系统把
2. 新增 `_is_pure_leak()` **整体判定**：三条同时成立才算纯泄漏
   - 有 ≥2 处第二人称祈使（你该/你不能/你要）
   - **没有任何数码产品名**（RTX/锐龙/拯救者…）
   - **没有价格数字**

命中后不走截断，直接改用**纯数据陈述**（从 `result.ranked` 取值拼，不让模型措辞）。

### 问题 2：「跑大模型」被推荐内存条（品类错配）

**现象**：「我要跑大模型，预算一万」→ `cat=upgrade` → 推「DDR5 32G 套条」

用户要整机，系统推了内存条。

**根因**：模型把「跑大模型」关联到「加内存」，判成 `upgrade`。实测 5 条变体：

```
我要跑大模型，预算一万             → upgrade ✗
想配一台能跑大模型的，一万          → upgrade ✗
我要一台能跑大模型的电脑，预算一万   → upgrade ✗  ← 明说"电脑"也判错
预算一万，跑大模型                → None ✓
一万块，要能跑大模型              → None ✓
```

**判据**：`upgrade` 只适用于**已有机器、只想换配件**（加内存/换固态/硬盘不够）。「跑大模型」是**用途**，不能反推品类。

**修法**：`cat=upgrade` 但有整机意图、无升级信号 → 改成 `None`（触发"笔记本还是台式"追问）。

⚠️ 不直接猜 thin/desktop——那是替用户做决定。

修复后：

```
我要跑大模型，预算一万      → cat=None，反问"笔记本还是台式" ✓
想配一台能跑大模型的，一万   → build_pc，装「本地模型主机」  ✓
加条内存 / 换个固态         → 保持 upgrade                  ✓
```

### 问题 3：「有几台能配」被判成统计

**现象**：「预算8000有几台能配」→ `stage=analyze`（统计全库），用户其实要装机。

**根因有两层**：
1. `intent_layer` 的 `_COUNT_ASK`（统计问法）抢走了装机意图
2. `agent.py` 的 analyze 分支有**独立规则兜底**，那里只否决了「推荐/换台」，没否决「装机」

第 2 层是主因——注释里 2026-11-23 修过「推荐几台」，当时只想到"推荐"，没想到"装机"。

**修法**：
- `intent_layer`：`_COUNT_ASK` 加 `_BUILD_HINT` 否决（有配/装/组就不算统计）
- `agent.py`：`_is_recommend` 补装机动作词（配得下/能配/装机/组装）
- `pc_build_intent.BUILD_PAT`：补可能补语形态（配得能下起出）

修复后：`build_pc` ✓，且「库里有多少游戏本」「有多少台带独显」仍是 `analyze` ✓

### 问题 4：`_WANT_BUILD` 覆盖不到「能配/配得下」

第一版只认「配 + 型号词」（配电脑/配主机），「能配」「配得下」都不匹配。补上补语形态后 8/8 正确。

## 三、没解决的问题（如实记录）

### 机型池 34 台缺链接

这 34 台 2026-11-09 从京东采集，当时没存 url 字段。尝试了三条路：

| 方法 | 结果 |
|---|---|
| ZOL 索引匹配（1460 个名称） | **0/34** |
| ZOL → 京东直达 | 无反查接口 |
| 京东搜索（urllib） | 2696 字节，反爬页 |
| 京东搜索（CDP 真实浏览器） | `Failed to fetch`（跨域/反爬） |

**根本原因**：这 34 台全是 2026 款新机，ZOL 还没收录（昨天就验证过同一现象）。

**当前影响**：这 34 台在推荐结果里**不可点击**（其他 209 台可点）。不影响推荐正确性。

**可行的解法**（需要人工）：
1. 手工去京东搜型号，填 34 个链接（约 30 分钟）
2. 或等 ZOL 收录后重抓

### 超长函数（技术债，非 bug）

```
agent.py    _run              1602 行  ← 最大
intent_layer classify          506 行
agent.py    answer_followup    438 行
build_pc    build_plan         459 行
```

`_run` 1602 行是 15 步有状态依赖的编排，拆分风险高（早上拆 `build_plan` 时踩了 3 次缩进坑）。**留待有完整回归网时再做**。

### 模型层仍有 11 条歧义（已知，规则已兜）

`unknown` 56.5%（有 focus 口径）——主要是「现在台式电脑多少钱一台」这类问价格行情的，语义确实模糊。规则能兜住大部分。
