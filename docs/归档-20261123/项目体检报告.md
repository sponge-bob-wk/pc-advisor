### 6.2 重点：nalyze 规则误伤（真 bug）

**现象**：

`
用户：「可以，放宽预算推荐几台」（上下文：7000 元轻薄本）
系统：stage=analyze
回答：「放宽预算后，华硕无畏 Pro16、华为 MateBook Pro S、
      联想小新 Pro14、拯救者 R9000P 和荣耀猎人游戏本
      这五台机型价格均为 7999 元。」
`

**完全荒诞** —— 用户要推荐，系统给了一句"五台同价"的废话。

**根因**：nalyze 的规则兜底正则里有 几台：

`python
r"多少台|几台|平均|中位数|分布|..."
`

几台 在「有多少台」里是**计数**，在「推荐几台」里只是**量词**。

**修法**：命中统计词之后，再看有没有明确的推荐/换台动作：

`python
_is_recommend = bool(re.search(
    r"推荐|推几台|给几台|来几台|看几台|挑几台|选几台|"
    r"换[一台两三四五六七八九十]|再来|再给|放宽|"
    r"帮我找|给我找|列几台|来几款|推荐几款", _t))
_want_analyze = _hit_stat and not _is_recommend
`

**为什么用否决而不是删掉 几台**：
「有几台带独显」是合法的统计问句，删了会漏。

**验证**：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| 可以，放宽预算推荐几台 | analyze ✗ | clarify ✓ |
| 推荐几台 | analyze ✗ | clarify ✓ |
| 再来几台 | analyze ✗ | clarify ✓ |
| 有多少台有独显 | analyze ✓ | analyze ✓ |
| 有几台带独显 | analyze ✓ | analyze ✓ |

**这是「规则兜底」的典型风险**：正则短、覆盖广，
但**语境一变就误伤**。而误伤的后果比漏判更严重 ——
用户要推荐，系统给统计，体验完全错位。

### 7.1 「啊啊啊」判成 refuse_switch —— 模型缺陷，不是 v4 引入

**实测对比**：

| 模型 | 「啊」×10 |
|---|---|
| qwen3.5-4b（当前线上） | **refuse_switch** ✗ |
| qwen3-4b-text | **unknown** ✓ |
| lora_v4（训过的） | refuse_switch ✗ |

**结论**：这是 qwen3.5-4b 基座自带的缺陷，**v4 没有引入也没有修复它**。

**可能原因**：训练集里 unknown 只有 15 条（占 2.7%），
样本太少，模型学不到「无实义 → unknown」这个映射。

**修法**（下次训练时做）：给 unknown 补样本。

`python
# 建议补 30-40 条
UNKNOWN_SEED = [
    ("啊", ), ("啊啊", ), ("嗯嗯", ), ("哦", ),
    ("。。。", ), ("？？", ), ("😀", ), ("哈", ),
    ("呃", ), ("这个", ), ("那个", ), ("就是", ),
    # 以及它们的重复形式
]
`

**优先级**：中。因为真实用户很少发「啊啊啊」，
但**这是「模型能力不足」的直接证据**，论文里可以诚实讨论。
