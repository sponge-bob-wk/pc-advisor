## 三、前端重构：1660 行 → 127 行

### 3.1 做了什么

```
tools/agent/
├── index.html      127 行（只有结构）
└── static/
    ├── style.css   44.8 KB（设计系统在 :root）
    ├── app.js      41.9 KB（统一状态对象 S）
    └── refresh.js   5.1 KB（刷新面板）
```

### 3.2 修的五类问题

| 手册要求 | 重构前 | 重构后 |
|---|---|---|
| 变量集中 | 2 个 `:root` | **1 个**，43 变量 12 分组 |
| 不许硬编码颜色 | **161 处 hex** | **0 处** |
| 统一状态对象 | 没有，8 个散落变量 | `S` + defineProperty 桥接 |
| apiCall 封装 | 5 处裸 fetch | 统一封装，检查 status+content-type |
| toast | 没有 | 有，2.2 秒自动消失 |

### 3.3 三个坑（都很隐蔽）

**坑 1：替换脚本把 `:root` 里的定义也改了**

```
结果：--bg: var(--bg);  --surface: var(--surface);  …（31 个自引用）
→ 整个样式崩掉
```

修法：先切出 `:root` 块原样保留，只替换块外部分。

**坑 2：`var` 声明遮蔽了 `defineProperty` 访问器**

```js
Object.defineProperty(window, 'slots', {get(){return S.slots}, ...});
var slots, asked, seen, ...;   // ← 这行让 window.slots 变成 undefined
```

修法：删掉 `var` 声明。

**坑 3：`refresh.js` 的 `$ is not defined` —— 原版就有的 bug**

原版两个 `<script>` 各自是 IIFE，`$` 定义在第一个，第二个用不到
→ **刷新面板其实一直是坏的**，但没人点过那个按钮。

修法：`app.js` 导出 `window.WB`，`refresh.js` 自带 `$`。

toast 自动消失 ✓  404 给人话 ✓  800px 无溢出 ✓  Console 无错误 ✓

## 四、数据补全

### 4.1 先纠正一个误判

`screenSizeIn`/`refreshHz`/`colorGamut` **不是 0%**，它们 100% 覆盖，
只是在 `screen` 子对象里。真正 0% 的是 `ports`/`cooling`/`brightness`/`dGPU`。

### 4.2 补全结果

| 字段 | 补前 | 补后 |
|---|---:|---:|
| `ports`（接口） | 0% | **91.5%**（204 台） |
| `cooling`（散热） | 0% | **29.1%**（65 台） |

### 4.3 关键教训

**写对位置才算补上。** 第一版写到顶层，但 `_pool_to_offer` 读的是
`m["screen"]["sizeInch"]` —— 数据进了 json，core 读不到，覆盖率还是 0。

**还要补投影。** `_pool_to_offer` 没投影这些字段，上层拿不到，
用户问「接口够不够」只能答"没记录"。

## 六、数据分析能力（毕设题目的核心缺口）

### 6.1 发现的问题

题目叫「数据分析大模型」，但系统**完全没有数据分析能力**。
实测 5 个分析类问题，**4 个被当成选机需求**回「是笔记本还是台式？」

这是答辩会被问死的地方。

### 6.2 新增 `analyze.py`

```
用户问「8000以内打游戏的机器平均多重」
  ↓ 模型：理解成 {agg: mean, field: w, filter: {price<=8000, cat=gaming}}
  ↓ 代码：确定性计算 → 2.49 kg（样本 18 台）
  ↓ 模型：组织成人话
```

支持 8 种操作：`count` / `mean` / `median` / `min` / `max` /
`groupby` / `distribution` / `top`。

### 6.3 实测效果

| 问题 | 回答 |
|---|---|
| 有多少台有独显 | 129 台 |
| 8000以内的游戏本平均多重 | 平均 2.49 kg（样本 18 台） |
| 各品牌机型数量对比 | 联想 97、华硕 36、惠普 26…共 14 组 |
| 32G内存的价格分布 | ¥4,189~¥84,999，5 档 |
| 性能最强的五台 | 拯救者 Y9000P 等 |

### 6.4 数字校验（重要）

**实测抓到模型编数**：

```
引擎算：平均 2.49 kg（样本 18 台）
模型说：「平均重量 1.75 公斤，基于 80 台有明确记录，其余 10 台未记录」
```

18→80，21-18=3 被写成 10，**两个数都是编的**。

**修法**：`_numbers_ok()` —— 回答里每个 2 位以上数字必须能在事实里找到，
找不到就退回纯事实拼接。

### 6.5 四个坑

1. **品类条件被漏掉**：模型解析「8000以内游戏本平均多重」漏了 `cat=gaming`，
   算成所有机器（80台/1.75kg）。两层修：提示词 + 代码从原话补。
2. **W8 结构性检查报错**：`test_weight` 不许出口层出现裸 `weightKg`。
   改成内部代号 `w`，取值走 `core.effective_weight`。
3. **analyze 意图抢走原有判断**：用 git 旧版对照实测，2 条是我改坏的。
   加两道规则否决（价格评价 / 升级版）。
4. **两个测试期望冲突**：`test_intent` 要 `ask_current`，
   `test_attack6` 要走 `compare` 算排名。**行为测试优先于标签测试**，
   从 `test_intent` 移除该句并注明理由。

## 十、答辩问答准备（写进归档了）

**Q：你说这是数据分析大模型，它到底分析什么？**
> 库里有 223 台机型的 40+ 个维度。用户可以用自然语言问聚合问题，
> 系统把问题解析成结构化查询，用代码算出统计量，再用模型组织成人话。

**Q：为什么不让模型直接算？**
> 两个原因。一是可靠性：模型算 223 台的平均值必然出错，
> 实测它连"这台排第几"都编过。二是可复现性：答辩要能说清每个数字
> 怎么来的，代码可以，模型不行。

**Q：那模型在这个系统里到底干什么？**
> 三件事：① 理解用户说什么 ② 把自然语言翻译成结构化查询
> ③ 把计算结果组织成人话。它不干：算数、排序、判断"够不够"。

**Q：怎么保证模型不改数字？**
> 出口有数字校验：回答里每个 2 位以上数字必须能在计算结果里找到，
> 找不到就退回纯事实拼接。实测抓到过它把"18 台"写成"80 台"。
