## 二、修了 10 个实际 bug

### 2.1 价格口径（用户反馈「价格很不准确」）

**根因**：223 台里有 **147 台（66%）只有「平台标价」**，没有真实到手价。
但模型输出经常只写「12499 元」，不说是到手价还是标价。

修三处：
1. 两处硬编码「到手 ¥%s」→ 改用 `_price_label()`
2. 出口补价格口径说明
3. 泄漏截断顺序错误（用旧位置截断，把刚补的说明砍了）

### 2.2 专业泛称被旧值覆盖

**现象**：第 1 轮「我学人工智能的」→ 第 2 轮「学设计的，预算 5100」
→ 专业还是「人工智能」，套用它的硬件要求（要独显），把 5100 以内轻薄本全筛掉，
推了 ¥12,999 的机器。

**根因**：`学设计的` 是泛称，`majors.json` 里没有，`match_major` 返回 None（这是对的）。
但槽位继承时**无条件沿用旧专业**，没区分「用户没提专业」和「提了但认不出」。

### 2.3 vramMin 被当成无条件硬门槛

**现象**：「我学视觉传达的，预算七千」→ 推了 ¥12,999。

**根因**：`majors.json` 里平面视觉组写着 `"gpu": "either"`（核显独显都行），
`tagline` 还说「吃色准和内存，不吃独显」。但代码把 `vramMin: 2` 当硬门槛，
把核显机器全筛掉。

**修法**：只有 `gpu == "discrete"` 时 `vramMin` 才是硬门槛。

### 2.4 Markdown 没渲染

**现象**：装机单在界面上显示成一堆原始符号（`###` 标题、`|` 表格线）。

**根因**：`parseReply` 只认「段落 + 数字列表」，不认 markdown。

**修法**：手写轻量 markdown 渲染器（60 行，支持标题/表格/引用/分隔线/粗体）。
不引第三方库 —— 项目原则是零框架依赖。

### 2.5 侧边栏遮挡

**现象**：「数据概览」文字随滚动遮挡侧栏内容。

**根因**：`.rail-hd` 是 sticky + 背景，但它是 `.rail` 的子元素，
而 `.rail` 有 `padding-left:24px` —— header 背景只覆盖内容宽度，
左侧 24px 留白没背景，内容从那道缝透上来。

### 2.6 折叠失效

**现象**：去掉 `open` 属性后侧栏高度还是 610px，折叠不生效。

**根因**：我加 `title` 时漏了 `</summary>` 闭合标签，
`.rg-body` 被浏览器当成 `<summary>` 的子元素 ——
而 `<summary>` 里的内容是**永远显示**的。

### 2.7 会话管理四个坑

| # | 坑 | 后果 |
|---|---|---|
| ① | `<script src="sessions.js">` 忘了加 | 用 `'sessions.js' in html` 检查，匹配到的是**注释里的文字** |
| ② | `window.WB.closeSide = ...` 在 window.WB 定义之前 | 抛 TypeError，整段 IIFE 中断，所有 UI 绑定不执行 |
| ③ | `getCur()` 返回 `''` 而不是 `null` | 新对话后发消息还是追加到旧会话 |
| ④ | `HERO_HTML` 只被使用从没定义 | 插入脚本锚点没匹配上，**静默失败** |

### 2.8 装机配置三个错误

| # | 错误 | 修法 |
|---|---|---|
| ① | 办公配了 GTX 1650 | 调低显卡比例只是选**便宜的**卡，不是**不配**卡 → 加 `needs_dgpu()` |
| ② | i5-12490F 配 RTX 5060 Ti | 显卡 ¥4,199 而 CPU 只有 ¥1,280，CPU 成瓶颈 → 加平衡检查 |
| ③ | 办公配 1250W 电源 | 电源按预算比例选是错的 → 改成按实际功率选最便宜够用的 |

### 2.9 SSD 抓不到

**根因有两层**：
1. `/ssd/` 返回 502，正确路径是 `/solid_state_drive/`
2. 即使找到，**页面结构完全不同**：

```
硬盘： <h3><a href="/hard_drives/index123.shtml">  → 一个商品一个价格

固态： <li data-follow-id="p1432186">
         <h3><a href="/series/626/...">    ← 系列链接
         <span class="price-type">359-1799</span>  ← 价格是区间
         <a href="/solid_state_drive/index1432186.shtml">  ← 单品链接
```

固态频道是「系列视图」，一个系列含多个容量，价格是区间。
装机单要的是**具体容量 + 具体价格**，所以要逐个抓单品页。

### 2.10 打游戏配 500G 固态、办公配 1T

**现象**：完全反了。

**根因**：只有一条通用底线「≥500G」，然后按价格比例挑。
游戏的预算大多给了显卡，留给固态的钱少 → 选到 500G。

**修法**：容量下限跟着用途走（`pc_rules.RULES`）。

## 四、关键设计决策（值得记住）

### 4.1 装机规则为什么要独立成 `pc_rules.py`

原来 `build_pc.py` 里散着魔法数字：

```python
ratio = {"cpu": 0.20, "gpu": 0.38, ...}
if ps & {"video", "threeD"}: minRam = 32
if budget >= 7000: 加机械盘
```

这些数字**没有出处**，改的时候不知道能改到哪、会影响什么。实战暴露了一堆问题。

现在抽成规则表，每个约束都带理由：

```python
RULES["gaming"]["minSsdGB"] = (1000,
    "3A 游戏单个 80-150G，500G 装两个就满了")
```

好处：
- 用户能看到「为什么给我配这个」
- 改规则时知道影响面
- 规则本身可以写测试

### 4.2 为什么台式机不推整机

整机池只有 2 台，排不了序。而且整机是别人配好的固定方案，改不了任何部件。
用户要台式的本质诉求就是「按我的需求配」，整机反而限制选择。

### 4.3 为什么 open-webui 要加适配层

open-webui 默认把提问**直接转发给模型**，会绕过 `agent.py` 里 7000 行的核心逻辑：
意图路由、确定性排序、22 条审计判据、价格口径校正、专业匹配。

加了 `openai_bridge.py`（402 行）做 OpenAI 兼容适配，保留全部能力。

### 4.4 为什么不用第三方 markdown 库

项目原则是「全栈零第三方框架依赖」。需要的语法就 5 种（标题/表格/引用/分隔线/粗体），
手写 60 行比引 30KB 的 marked.js 划算。

## 九、今天踩坑的共同模式

回头看这 10 个 bug，有三个反复出现的模式：

### 模式一：检查了，但检查错了对象

- `<script src="sessions.js">`：用 `'sessions.js' in html` 判断，
  匹配到的是**注释里的文字**，实际标签没加
- `HERO_HTML`：插入脚本的锚点没匹配上，**静默失败**，
  代码里只留下 `h.innerHTML = HERO_HTML` 却没有定义

**教训**：验证要看**实际产物**，不是看自己写的检查逻辑。

### 模式二：两段文本变换有依赖，顺序反了就白做

- 价格补全先执行、泄漏截断后执行，
  但泄漏检测的位置是基于**补全前**文本算的 → 把刚补的说明砍了
- 侧栏 sticky 背景在父元素 padding 内 → 盖不住

**教训**：文本/布局的变换链要考虑依赖顺序。

### 模式三：只测字符串，没测渲染结果

- markdown 输出：`agent.run()` 返回的 `reply` 里 markdown 是正确的，
  但前端完全不认 markdown，用户看到一堆原始符号

**教训**：改输出格式必须在浏览器里看实际渲染，不能只看字符串。
