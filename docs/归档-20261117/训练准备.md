## 3. 五个关键设计决策（都写进脚本注释了）

### ① 只对 assistant 算 loss

```python
full_ids = tok(full, ...)["input_ids"]
prefix_ids = tok(prefix, ...)["input_ids"]   # 到 assistant 之前
labels = [-100] * n_prefix + full_ids[n_prefix:]
```

**为什么**：如果对 user/system 也算 loss，模型会学着"复述用户的话"。

### ② `max_length=1024` 而不是更长

路由层输出很短（思维链 3~5 句 + JSON）。1024 够用且省显存。

### ③ `lora_alpha = 2 * r`

标准做法（原论文推荐）。alpha/r 的比值决定更新幅度。

### ④ `target_modules` 选七个

```python
["q_proj", "k_proj", "v_proj", "o_proj",      # 注意力
 "gate_proj", "up_proj", "down_proj"]          # MLP
```

只训注意力效果不够，全训显存吃紧 —— 七个是平衡点。

### ⑤ 不用 trl 的 SFTTrainer

环境没装 trl。手写循环更好控制（以后可以按 intent 分桶采样）。

## 4. 8GB 显存下的保守配置

```python
batch_size    = 1      # 只能 1
grad_accum    = 8      # 等效 batch = 8
lr            = 2e-4
epochs        = 3
lora_r        = 16
optim         = "paged_adamw_8bit"   # 省显存
gradient_checkpointing = True
bf16          = True
```

**如果 OOM**（显存不够），按这个顺序降：

1. `max_length` 1024 → 768
2. `lora_r` 16 → 8
3. `target_modules` 去掉 MLP 三个（只训注意力）
