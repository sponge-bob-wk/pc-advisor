## 1. 为什么真实日志最值钱

| 来源 | 例子 |
|---|---|
| 我手写的模板 | 「这台不要了换一个」 |
| **真实用户说的** | 「那我不想要这种的」「再看看别的」「换一台这台我不想要」 |

**语气、省略、口语化程度完全不同。**
用模板训出来的模型，遇到真实用户会懵。

日志里有 **443 条原始句子，去重后 145 条**（过滤掉 <3 字和内部测试标记）。

---

## 2. 核心难题：日志没有金标签

日志只有 `text` + `stage`，没有 `{intent, topic, fit}`。

**只靠模型打标 = 用可能错的标签训练。** 所以设计了**三重校验**：

```
① 模型预测
② 规则复核（intent_layer.classify(allow_model=False)，独立于模型）
③ 交叉验证（改个无关词再问，看判断稳不稳）
```

三关都过的才收。

---

## 3. 三次修正判据（每次都是实测逼出来的）

### 第一版：要求「规则和模型完全一致」

结果：145 条只收 **55 条（37.9%）**，排除 83 条。

查下来 **74 条是"规则判 unknown"**：

```
「学设计的，五千，要用四年，平时背去教室」  规则=unknown  模型=ask_current
「5000 的轻薄本，就上课写作业」           规则=unknown  模型=state_range
「要带去教室」                       规则=unknown  模型=state_new_need
```

**纯规则层认不出这些真实句子** —— 它只会词表匹配，真实用户的省略/口语化它接不住。

**这是规则的能力不足，不是模型判错。** 用它排除等于把最好的数据扔掉
（真实日志的价值恰恰在于"规则认不出、模型认得出"）。

**修法**：规则判 `unknown` 时**不算反对**，只在"规则有明确判断且与模型冲突"时排除。

效果：**37.9% → 89.0%**（收 129 条，只排除 9 条真冲突）。

### 第二版：加「自一致性」（同一句问两次）

结果：**「两次判断不一致 = 0」**。

因为 `route()` 有缓存，而且 **temperature=0 时模型输出确定性**，
同一句问 100 次都一样。**这个判据根本抓不到错。**

### 第三版：改成「同类交叉验证」（改一个无关词再问）

```
「学设计的，五千，要用四年，平时背去教室」→ ask_current ✗
「学设计的，预算7000，要带去教室」       → state_new_need ✓
```

同一类句子判断不一致 —— 说明模型在这类上**不稳定**。

**修法**：把句子里的数字换掉再问。数字不该改变意图类别 ——
如果换了数字意图就变了，说明模型是靠某个词在猜，不是在理解语义。

效果：抓到 **7 条不稳定样本**，收录 122 条（84.1%）。

## 4. 抓到的 7 条不稳定样本（很有价值）

| 原句 | 原判 | 变体 | 变判 |
|---|---|---|---|
| 5000 的轻薄本，就上课写作业 | `state_range` | 5001 的轻薄本… | `state_new_need` |
| 32G内存不能更改也行吧，够用了 | `ask_current` | 33G内存… | `state_new_need` |
| 预算 5000 写代码 | `state_new_need` | 预算 5001 写代码 | `state_range` |
| 预算 12000 打 3A | `state_new_need` | 预算 12001 打 4A | `state_range` |
| 预算 6000 学设计 | `state_new_need` | 预算 6001 学设计 | `state_range` |
| 预算 12000，打 3A | `state_new_need` | 预算 12001，打 4A | `state_range` |
| 暗影精灵 11 锐龙版 怎么样 | `ask_current` | 暗影精灵 12 锐龙版 怎么样 | `refuse_switch` |

### 最值得注意的：「预算 N + 用途」句式

```
「预算 5000 写代码」   → state_new_need ✓
「预算 5000，写代码」  → state_range   ✗   ← 只多了一个逗号
「预算 8000 打游戏」   → state_range   ✗
```

**标点改变判断** —— 说明模型靠「写代码」的位置在猜，不是理解语义。

这个句式**本身有真实歧义**：

| 句子 | 该判什么 | 为什么 |
|---|---|---|
| 预算 5000 | `state_range` | 只说价位 |
| 预算 5000，写代码 | `state_new_need` | 预算 + 用途 |
| 一万以内打游戏的有什么推荐 | `state_range` | 有「有什么推荐」= 索取动作 |

**判据**：有没有「推荐/有什么/看看」这类**索取动作** ——
有就是 `state_range`，没有就是纯给条件。

这 3 条已收进纠错集（带明确判据）。
