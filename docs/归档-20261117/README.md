## 发现误判时的判断标准

| 类型 | 例子 | 处理 |
|---|---|---|
| 模型判错 | 「限电500W」判成问电池 | ✅ 收进 `corrections.jsonl` |
| 系统没实现 | 「可以」该调 budget 却没调 | ❌ 不收，写进缺陷记录 |
| 数据缺失 | 「保修几年」答不知道 | ❌ 不收，去补数据 |

**判据**：模型的 `{intent,topic,fit}` 换成对的值就能答对 → 模型判错；
换什么值都答不对 → 代码或数据问题。

### 2. 价格多来源交叉验证

新增 `price_cross_check.py`。126 台有 ≥2 个价格来源可互比。

**抓到一个真问题**：`merchantMin` 是串台的（`6434` 出现 9 次，
落在型号配置完全不同的机器上，是 ZOL 侧栏推荐位价格）。
已自动识别并排除。

剩余 15 台 `tmall` 与 `zolRef` 偏差 >30%（8G/16G SKU 串台），待逐台核对。

### 3. 修「问细节却回头问槽位」

```python
agent.run('有别的颜色吗', focus='zol-2130961')
# 修前 → clarify「是笔记本还是台式？」
# 修后 → followup「这台只有雾屿白一种颜色」
```

根因：`focus` 只带 id 不带槽位，`missing_required(slots)` 缺「品类」触发 clarify。

修法：有 focus + 在问这台的某一面 → 直接答细节，跳过槽位收集。

**顺带修好一条存量失败**：`test_intent` 72/74 → 73/74。
