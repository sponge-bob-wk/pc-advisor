# 训练集：真实误判纠正机制（2026-11-17）

> 用户要求：「那就纠正模型理解的样本作为训练集，记得随时收集训练集后续微调」

---

## 1. 为什么单独做一套

现有三个收集器**都不管"模型判错了"这件事**：

| 脚本 | 管什么 | 不管什么 |
|---|---|---|
| `harvest_samples.py` | 给存量提问补**回答** | 不判对错 |
| `adversarial_harvest.py` | 手写模板造**对抗样本** | 不是真实误判 |
| `harvest_from_logs.py` | 从日志抽**真实句子** | 不知道模型判对没判对 |

**真实误判是最贵的训练数据**：

- 它是模型在**当前版本**下确实会错的地方
- 比手写模板更贴近真实分布
- 每条都带 `wrong`（错误输出），可作 DPO 负样本

## 2. 新增 `collect_corrections.py`

### 2.1 样本格式

```json
{
  "messages": [system, user, assistant(正确答案)],
  "_meta": {
    "correct_before": false,
    "wrong": "{\"intent\":\"ask_current\",\"topic\":\"battery\",\"fit\":true}",
    "why": "「限电500W」是补充条件，不是问电池；模型被「电」字带偏",
    "src": "correction:2026-11-17",
    "found": "chat-2026-11-17.log 第 11 条（用户实测）",
    "actionable": true
  }
}
```

`_meta.wrong` 是关键 —— **它记录模型当时的错误输出**，
将来做 DPO / 拒绝采样时就是天然的负样本。

### 2.2 标签校验（不许省）

进训练集前必须过 `validate()`：

- `intent` 必须在 6 个合法值里
- `topic` 必须在 11 个合法值里
- `fit` 必须是布尔
- **`correct` 与 `wrong` 不能完全相同**（相同就不是误判样本）

实测这条校验当场拦住了一条：

```
✗ 跳过 可以：correct 与 wrong 完全相同 —— 这条不是误判样本
```

「可以」这条的 intent 判断其实是对的（`state_new_need`），
错的是**系统动作没实现**（该调 budget 却没调）。
它不该混进"模型判断错"的样本里，否则会教模型一个错误的方向。

### 2.3 首批 2 条（今天实测的）

| 用户原话 | 模型判的 | 正确 | 为什么错 |
|---|---|---|---|
| 限电 500W | `ask_current` / `battery` / fit=True | `state_new_need` / `none` / fit=False | 被「限电」里的「电」字带偏，当成问电池 |
| 我想打游戏 | `state_new_need` / `none` / fit=**False** | `state_new_need` / `none` / fit=**True** | 说了用途就该判 fit=true，下一句要判"当前这台够不够" |

## 3. 接进训练集构建

`build_route_lora.py` 的 `SOURCES` 加了 `corrections.jsonl`。

### 3.1 踩到一个坑：最贵的样本被切进了 eval

首次重建后：

```
route-train.jsonl 含纠错样本 0 条: []
route-eval.jsonl  含纠错样本 2 条: ['限电 500W', '我想打游戏']
```

哈希切分把两条纠错样本**全切进了评估集**，
训练集一条都没有 —— 等于"最贵的样本没拿去训练，只拿来考试"。

### 3.2 修法：强制进训练集，同时保留在 eval

```python
for r in uniq:
    src = str((r.get("meta") or {}).get("src") or "")
    if "correction" in src:
        train.append(r)
        evalset.append(r)      # 故意重叠：必考项
        continue
    # 其余按哈希切分
```

**为什么故意让训练集和评估集重叠**：

- 这类样本的价值在于让模型**学会不再犯同样的错** → 必须训练
- 同时要能验证"上次那个错现在还会不会犯" → 必须评估
- 代价是 eval 分数会偏乐观，但这两条是**已知必考项**，
  宁可分数保守也要盯着它们

重建后：

```
切分：训练 355 / 评估 36（eval-ratio=10%）
      其中 2 条实测误判纠正样本强制进训练集（同时保留在评估集）
```

## 5. 怎么用

```bash
cd tools/agent

# 看已收集多少
python collect_corrections.py --list

# 写入 2026-11-17 首批（幂等，重复跑不会重复写）
python collect_corrections.py --seed

# 交互式添加一条（下次发现新误判时用）
python collect_corrections.py --add

# 重建训练集（把纠错样本并进去）
python build_route_lora.py --write

# 复核账目
python lora_status.py
```

## 6. 下次发现误判时的标准动作

用户实测发现问题 → **先判断是"模型判错"还是"系统没实现"**：

| 类型 | 例子 | 处理 |
|---|---|---|
| 模型判错 | 「限电500W」判成问电池 | ✅ 收进 `corrections.jsonl` |
| 系统没实现 | 「可以」该调 budget 却没调 | ❌ 不收；这是代码 bug，写进缺陷记录 |
| 数据缺失 | 「保修几年」答不知道 | ❌ 不收；去补数据 |

**判据**：模型给出的 `{intent, topic, fit}` 如果**换成一个对的值就能让系统答对**，
那是模型判错，该收；如果**无论模型怎么判系统都答不对**，那是代码或数据问题。
