# 思维链蒸馏 + 对抗测试（2026-11-17 深夜）

> 用户要求：「你不是每次纠正他，可以不仅仅是问题和答案，
> 也可以把你思考的思维链给他，这样蒸馏效果不是更好吗，
> 你可以对抗测试收集蒸馏数据」

这个判断是对的。**只给答案的蒸馏，学生学的是"背结论"。**

---

## 1. 为什么思维链有用

| 只给答案 | 给思维链 |
|---|---|
| 「限电500W → state_new_need」 | 「给出具体数值条件 = 在补充约束」 |
| 换个说法就不会 | 能推广到「宿舍限电300瓦」「预算卡死6000」 |

**思维链教的是判断方法，不是记忆。**

### 但也有风险（三条，都在代码里防了）

| 风险 | 后果 | 防法 |
|---|---|---|
| 思维链本身是错的 | 教错判断方法，比不给更糟 | 只收**模型判对**的；模板样本的判据人工写 |
| 循环论证（「因为答案是X所以是X」） | 学生学不到东西 | 模板强制写「关键区分点」 |
| 学生模型太小，输出格式乱 | 推理时 `json.loads` 全失败 | 加 `_extract_json` 容错 |

## 2. 关键改动：`_extract_json`（不做这个，训练了也用不上）

原来推理端是严格解析：

```python
d = json.loads(out)      # 对「思维链+JSON」必然抛异常
```

抛异常 → 被当成"模型失败" → **整个模型路由降级成纯规则**。
训练了 CoT，推理时反而全废。

改成从后往前找最后一个能解析的 JSON：

```python
def _extract_json(text):
    end = len(s)
    while True:
        i = s.rfind("{", 0, end)
        if i < 0: return None
        # 从 i 找匹配的 }，试解析
        ...
        end = i      # 不行就往前找
```

**为什么从后往前**：最终答案在思维链之后。

自测 6/6 通过：

| 形态 | 结果 |
|---|---|
| 纯 JSON | ✓ |
| 思维链 + JSON | ✓ |
| markdown 代码块 | ✓ |
| 多段 JSON（取最后） | ✓ |
| 无 JSON | 返回 None（降级） |
| 空串 | 返回 None |

**判错的 5 条全在「补充条件」和「换台」这两类。**

### 5 条判错的详情

| 句子 | 模型判的 | 正确 |
|---|---|---|
| 宿舍限电 300W 能用吗 | `ask_current/config/fit=True` | `state_new_need/none` |
| 预算卡死 6000 不能再高了 | `state_range/price` | `state_new_need/none` |
| 得能带去教室，太重的不行 | `ask_current/weight/fit=True` | `state_new_need/none` |
| 平时主要打游戏 | `ask_current/config/fit=True` | `state_new_need/none` |
| 再看看别的吧 | `list_others` | `refuse_switch` |

**共同模式：模型把「补充条件」判成 `ask_current`**，
而且常伴 `fit=True` —— 它以为用户在问"这台行不行"。

这 5 条**进了 `corrections.jsonl`**（纠错流程），**不进蒸馏集**——
因为它们的思维链是"事后补的正确判据"，不是模型当时的真实推理。
混进蒸馏集会教模型"先猜错再纠正"。


**为什么分开**：

| 文件 | 用途 | 训练时怎么用 |
|---|---|---|
| `cot-route` | 教判断方法 | 直接进训练 |
| `corrections` | 记录模型会错在哪 | 强制进训练（防止再犯） |
| 两者混合 | ❌ 不行 | 纠错样本的 CoT 是补的，不是真实推理 |

## 6. 思维链写作规矩（写进代码注释了）

```
① 必须写出关键区分点 —— 为什么不是另一个标签
② 不许写"因为答案是 X 所以是 X"（循环论证）
③ 要能推广 —— 用「补充条件」而不是「限电这个词」
④ 3~5 句，别写成小作文
```

### 好的例子

```
这句在说一个使用条件（宿舍限电功率），不是在问这台的某一面。
「电」字容易被带偏成电池/续航，但整句没有疑问形态，
也没有问「这台的电池怎么样」。
判据：给出一个具体数值条件 = 在补充约束，要记进槽位并据此重判。
所以 intent 是 state_new_need，topic 给 none —— 它不是在问某个面。
{"intent": "state_new_need", "topic": "none", "fit": false}
```

**注意它做了三件事**：
1. 点出陷阱（「电」字容易被带偏）
2. 给判据（给出具体数值条件 = 补充约束）
3. 得出结论

### 坏的例子（没这么写，但要知道什么不行）

```
这句话的答案是 state_new_need。
{"intent": "state_new_need", ...}
```

循环论证，学生学不到任何可推广的东西。
