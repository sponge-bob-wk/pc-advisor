## 1. 缺陷 F：`fit`/`followup` 分支不做槽位抽取 → purpose 丢失

### 证据

```
[13] 拿他打游戏  → stage=followup  known.purpose=None
[17] 打游戏     → stage=followup  known.purpose=None
```

但单句抽取是对的：

```python
agent.extract_slots('拿他打游戏')  →  {'purpose': ['gaming'], ...}   ✅
agent.extract_slots('打游戏')     →  {'purpose': ['gaming'], ...}   ✅
```

### 根因：模型把「打游戏」判成了 `ask_current`

```python
intent_layer.route('打游戏', focus='thin-matebookd16')
# → intent=ask_current, topic=config, fit=False

intent_layer.route('我想打游戏', focus='thin-matebookd16')
# → intent=state_new_need     ← 只差「我想」两个字
```

| 输入 | intent | `refers_to_current` | 走哪个分支 |
|---|---|---|---|
| 打游戏 | `ask_current` | **True** | followup → **不抽槽位** |
| 拿他打游戏 | `ask_current` | **True** | followup → **不抽槽位** |
| 我想打游戏 | `state_new_need` | False | 正常流程 → 抽槽位 |

**模型过度依赖「我想/我要」这类显式标记。**
上一轮系统问「主要拿来干什么？」，用户答「打游戏」——这是**在回答用途问题**，
不是问当前这台。模型判错了。

### 处理

已收进训练集（`corrections.jsonl`）：

- `打游戏`：`ask_current/config` → `state_new_need/none`
- `拿他打游戏`：`ask_current/config` → `state_new_need/none`
- `那换一台吧`：`ask_current/none` → `refuse_switch/none`

## 2. 缺陷 G：用途变 gaming，但品类被上一轮的 thin 压住

### 证据

修好 intent 之后仍然有问题：

```python
agent.run('我想打游戏', known={'cat':'thin','budget':10000}, focus='thin-matebookd16')
# → slots: {'cat': 'thin', 'purpose': ['gaming']}   ← 用途对了，品类还是轻薄本
# → 推荐：红米 Book Pro 14（轻薄本）
```

### 根因

`agent.py` 的继承逻辑：

```python
cur = slots.get(k)
if cur is None or cur == [] or cur == "":
    if known.get(k) is not None:
        slots[k] = known[k]      # cat 本轮没抽到 → 继承 thin
```

然后下游的推导：

```python
if not slots.get("cat") and "gaming" in purpose:
    slots["cat"] = "gaming"      # 永远不成立，cat 已经被继承成 thin
```

### 修法

在继承之后加一条**冲突消解**：

```python
_purpose_now = set(slots.get("purpose") or [])
if "gaming" in _purpose_now and slots.get("cat") == "thin":
    slots["cat"] = "gaming"
```

理由：「打游戏」这个用途本身就决定了品类，不该被上一轮的 `cat` 压住。

⚠️ **反向不成立**：purpose 里有 design/code 时，cat 可以是 thin 也可以是 gaming，
两种都合理，所以不做反向强制。

### 效果

```
修前：slots={'cat':'thin','purpose':['gaming']}   → 推荐红米 Book Pro 14
修后：slots={'cat':'gaming','purpose':['gaming']} → 推荐惠普暗影精灵 11 ✅
```

## 3. 缺陷 H：`seen` 从不累积 → 换台时不知道看过什么

### 证据

```
[12] stage=fit       seen=None
[13] stage=followup  seen=None
[14] stage=clarify   seen=None   ← 「换一台」时不知道看过啥
```

### 根因

`fit` 和 `followup` 分支的返回值里**没有 `seen` 字段**，
`run()` 的兜底只是 `out["seen"] = list(seen or [])` —— 透传，不累积。

所以：`seen` 永远是 `None`（前端也没传），换台时系统把看过的机器又推一遍。

### 修法

兜底时**把当前 focus 补进 seen**：

```python
if isinstance(out, dict):
    _cur = out.get("focus")
    if _cur and _cur not in (out.get("seen") or []):
        out["seen"] = list(out.get("seen") or []) + [_cur]
```

### 效果

```
修前：[12] seen=[] → [14] 换台时 seen=[]，推回同一台
修后：[12] seen=['thin-matebookd16'] → 换台能排除它
```

## 5. 还没修的：缺陷 I（换台时重复问已知信息）

### 现象

### 根因（初步）

**注意**：§1 的缺陷 F 修好后（purpose 不再丢），这个问题可能自动缓解 ——
但需要重新实测确认。

## 6b. 缺陷 H 的完整修法（后端 + 前端两处都漏）

`seen` 不累积这件事，**后端和前端各漏一次**：

### 后端：`run()` 只透传不累积

```python
# 原来
if out.get("seen") is None:
    out["seen"] = list(seen or [])     # 透传，seen 是 None 就还是 None
```

改成兜底时把当前 focus 补进去：

```python
if isinstance(out, dict):
    _cur = out.get("focus")
    if _cur and _cur not in (out.get("seen") or []):
        out["seen"] = list(out.get("seen") or []) + [_cur]
```

### 后端：`slim_result()` 没投影 `seen`

```python
# server.py 的响应白名单里没有 seen
out = {"stage":..., "reply":..., "slots":..., "asked":..., "focus":...}
```

→ 前端永远拿不到。补 `if r.get("seen"): out["seen"] = r["seen"]`。

### 前端：只从 `kernel.ranked` 攒

```js
// 原来
((d.kernel&&d.kernel.ranked)||[]).forEach(function(x){
  if(x&&x.id&&seen.indexOf(x.id)<0) seen.push(x.id);
});
```

`fit` / `followup` 分支**没有 `kernel.ranked`**，所以前端一条都不记。

改成优先用后端的 `d.seen`，`kernel.ranked` 作为补充。

### 三处都修完的实测

```
Q: 那换一台吧  （带 known/seen/focus）
  stage: recommend
  focus: zol-2128706        ← 换了新机器
  seen: ['zol-2128664', 'zol-2128706', 'add-tianxuan6pro', 'zol-2139965']
```

> ⚠️ **测试方法提醒**：用 PowerShell 的 `ConvertTo-Json` 发中文会转义坏，
> 必须用 Python 的 `json.dumps` 发。本轮我在 PowerShell 里测出"全空"，
> 差点误判成代码 bug —— 换 Python 发立刻正常。

## 8. 给下一个接手者

1. **「打游戏」这类短句的 intent 判定是薄弱点** ——
   模型要靠「我想/我要」才判对，没有这两个字就判成 `ask_current`。
   已收 3 条纠错样本，但可能还有别的说法没覆盖（「主要玩游戏」「游戏为主」）。
2. **槽位抽取只在"正常流程"里发生** ——
   `fit`/`followup` 分支不抽槽位，所以任何被误判进这两个分支的"给条件"句子
   都会丢信息。这是结构性问题，不只是「打游戏」这一句。
3. **`seen` 现在会累积了**，但要确认前端确实在传它。
   如果前端不传，后端每次从空开始，换台仍然会重复。
