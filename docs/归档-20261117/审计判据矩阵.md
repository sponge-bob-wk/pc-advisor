# 审计判据矩阵（2026-11-17 晚）

> 起因：修 `ask_fit` 时发现 `_power_guess` 只加在一条路径上，
> 另外三条路径同样会编功耗。
>
> 这已经是「判据抄两遍一定会漂」的**第七次**复现。

---

## 1. 问题：判据散在四个函数里，没人知道谁漏了

四条输出路径，各有各的审计：

| 路径 | 什么时候走 | 审计函数 | 判据数 |
|---|---|---|---|
| `compose()` | 首轮推荐 | `_audit` | 11 |
| `answer_followup()` | 追问细节 | `_f_audit` | 9 |
| `_answer_current()` | 判用途匹配 | `_bad_answer`（内联） | 8 |
| `_intro_model()` | 介绍机型 | `_bad`（内联） | 6 |

**没有一处能一眼看出"谁有谁没有"。** 所以每次改完一条路径就以为改好了。

历史战绩（七次）：

1. `compose` 有「参数当卖点」，`answer_followup` 漏了
2. `compose` 有「偷换推荐对象」，追问路径漏了
3. `_answer_current` 完全没有审计（2026-11-17 才发现）
4. `_power_guess` 只加在 `_answer_current`，另三条同样会编功耗
5. `check_fabrication` 在 followup 路径完全没有
6. `_warranty_stretch` 只在 `compose` 有
7. `_overspec` 在 followup 漏了

---

## 2. 做了什么：`audit_matrix.py`

把四条路径各自用到的判据列成矩阵，缺的用 `·` 标出来：

```
判据                     compose followup current intro
  _overspec               ✓           ✓           ✓           ✓
  _power_guess            ✓           ✓           ✓           ·
  check_fabrication       ✓           ✓           ✓           ✓
  _warranty_stretch       ✓           ·           ·           ·
  _tangent                ·           ✓           ·           ·
```

```bash
python audit_matrix.py            # 打印矩阵
python audit_matrix.py --gaps     # 只列缺口
python audit_matrix.py --strict   # 有缺口退出码 1（接 CI）
```

### 实现方式（静态分析，不是运行时）

读源码 + 正则抽判据调用名。局限性写在脚本头部：
如果判据是先赋值给变量再调用，可能识别不到 —— 那时手工补进 `NOT_JUDGE` 表。

## 3. 本轮补的三条（「不许编造」类，必须全路径覆盖）

| 判据 | 原来覆盖 | 现在 |
|---|---|---|
| `check_fabrication`（编造数字） | compose / current / intro | **四条全** |
| `_overspec`（超证据断言） | compose / current / intro | **四条全** |
| `_power_guess`（功耗推测） | 只有 current | **四条全** |

补的时候每处都要加两样东西：

1. `_audit` / `_bad` 字典里加判据
2. `why` 列表里加对应说明（否则重写提示词不知道错在哪）

**只加判据不加 `why` 是个坑**：模型被要求重写，但不知道哪里错了，
重写完大概率还是错的。

---

## 4. 还剩的缺口（下轮处理）

矩阵里还有 13 个缺口，多数是"这条判据只对某类路径有意义"，
但有 4 个值得补：

| 判据 | 缺 | 为什么值得补 |
|---|---|---|
| `verify_answer`（数字可追溯） | followup / intro | 追问时同样可能编数字 |
| `_out_scope_product` | followup | 追问时会冒出"手机""工作站" |
| `_field_echo`（念字段名） | followup | 追问路径最容易念字段名 |
| `_other_model_pitch` | current | 匹配判断时可能安利另一台 |

**不建议盲目全补**的：

- `_tangent`（跑题）：只对追问有意义
- `_too_thin`（太短）：首轮推荐本来就长
- `_budget_lie` / `_cross_cat` / `_relative_claim`：只对推荐场景成立

## 6. 给下一个接手者

1. **改判据前先跑 `python audit_matrix.py`** ——
   它会告诉你这个判据现在覆盖了哪几条路径，你改完再看一遍确认。
2. **加判据必须同时加 `why`** —— 否则模型不知道该改什么。
3. **`--strict` 可以接进 CI** —— 但先接受现有 13 个缺口，
   否则 CI 一直是红的。建议改成"白名单"：只对
   `check_fabrication` / `_overspec` / `_power_guess` 三条做强制检查。
