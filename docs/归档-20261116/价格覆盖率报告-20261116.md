## 3. 为什么 `net`/`final` 还是 33.9%

这两个字段只认**京东商品页直读**，而京东要求登录。本轮实测：

| 通道 | 结果 |
|---|---|
| `p.3.cn/prices/mgets` | 连接超时 |
| `item-soa.jd.com/getWareBusiness` | 返回风控页 |
| `item.jd.com` PC 页 | 35KB 空壳，价格异步渲染 |
| `search.jd.com` | 重定向 `risk_handler` |
| `item.m.jd.com` 移动页 | 能打开，价格下发占位 `"price":"1"` |

按用户 2026-11-16 指示「三方也可以，不用京东」，本轮接了 ZOL 三方源，
把 **list 与快照价补到 97.5% / 99.6%**，但**没有**把快照价冒充 net/final ——
那会让「电脑涨价分析」的涨幅计算全部失真。

## 4. 踩过的坑：天猫价污染了 51 台 `price.list`

ZOL 详情页有三个价格容器，**只有前两个准**：

| 容器 | 含义 | 可信 |
|---|---|---|
| `price__reference` | 参考报价 | ✅ 每台都不同 |
| `_j_local_price` | 经销商区间 | ✅ |
| `FreeVer2_tmall` | 天猫价 | ❌ **落在推荐位里** |

硬证据：3 台配置完全不同的「机械革命极光X」（RTX4060/4060/4070）
拿到**同一个**天猫价 5788；全量统计 `tmall` 里 6500 出现 9 次、
8698/5788/18799 各 5 次，而 `zolRef`/`jd` 的重复度都在正常范围。

污染后果：50 台 `price.list` 被写成天猫价，偏差最大 **±14500**
（`zol-2125908` 15499→29999）。已由 `fix_list_from_zolref.py` 全部校正回 `zolRef`，
并把重复值的天猫快照从库中清掉。
