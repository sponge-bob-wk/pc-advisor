## 每份文档讲了什么（一句话）

### `数据补齐报告-20261116.md`（11.7 KB）

**根因**：`zol_fetch.py` 里有一句注释断言「ZOL 参数表没有 CPU型号/内存容量/硬盘容量/分辨率」——
**这句是错的**，参数页 56 个字段里全都有。按标题型号串正则抠，导致
`cpu.cores` 缺 163 台、`gpu.vramGB` 缺 167 台。

**修的四类错**：
1. `screen.gamut`/`brightness` 键名与判定引擎读的 `colorGamut`/`brightnessNit` 不符
   → 86 台色域、96 台亮度**在库里但读不到**
2. CPU 厂商「非 AMD/Apple 一律判 Intel」→ 麒麟 XE90 被标成 Intel
3. `skuLabel` 残渣当 CPU → 5 台 Intel 机器被标成 Apple M4/M5
4. 端口数组按逗号无脑切 → 华为折叠本括号被劈开

**结果**：R 级缺口 1001 对 → 147 对。

### `价格覆盖率报告-20261116.md`（3.3 KB）

京东要登录抓不到，改接 ZOL 三方源。`price.list` 补到 97.5%。

**核心纪律**：三方快照价**只进 `priceSnapshots` 或 `price.list`，永不进 net/final**——
那是「到手价」语义，塞快照价能凑 100% 覆盖率，代价是涨幅计算全错。

**踩的坑**：ZOL 详情页的 `tmall` 价落在推荐位里（3 台不同配置的极光X 拿到同一个 5788），
污染了 51 台 `price.list`，偏差最大 ±14500。

### `跑分覆盖提升-20261116.md`（9.3 KB）

**先纠正了交接文档的错误结论**：旧文档说「剩余无跑分一半是 CPU 只写系列名」，
实测 92 台里系列名只有 1 台、具体型号 90 台。

**三个额外发现**：
1. 交叉验证的 `rho=0.500` 是**假的** —— 字段名不一致（`gb6` vs `geekbench6`），
   修完 16 颗样本、rho=0.947
2. 三颗芯片「有原始分但没算 perf」→ 补算后无分芯片归零
3. `verify_bench` 把「功耗墙差异」误判成「数据错」→ 不合格 2 → 0

**Notebookcheck 已可达**（交接时记录的国际跑分站全 000 已不成立）。

### `优缺点覆盖-20261116.md`（7.9 KB）

**问题**：223 台里只有 34 台有人工优缺点，其余问「有什么缺点」只能答"没评价"。

**试过两条抓评测的路都不行**：
- ZOL 点评页 → `class="empty-comment"`，绝大多数机型没有
- ZOL 评测文章 → 抽出来的是导购文对**多台机器**的泛泛比较，不是本机缺点

**换的路**：只陈述「规格里的事实」（`upgrade=0` → 内存焊死；`weightKg=2.5` → 偏重）。
新增 `derive_notes.py`，产出 786 条，222 台覆盖。

**三个坑**：空列表喂给模型它会念「优点为空」；拼成一句只挑一条说；
自家事实被审计判成"串台"（`_one_corpus` 没收录 `derivedNotes`）。

### `数据刷新与措辞调整-20261116.md`（9.8 KB）

**两件事**：
1. 去掉「人工/没人评过」的措辞（15 处提示词 + 8 处前端/字段卡）
2. 加「↻ 刷新数据」按钮：触发+轮询（全量抓取 3-5 分钟，同步等会超时）

**五个坑**：预设依赖不闭合导致整条链被跳过；脚本不在同一目录；
前端用相对路径没有 `API` 前缀；统计刷新函数名写错且静默失败；
**顺手抓到 1000kg 的笔记本**（7 台把「克」当「千克」）。

### `追问维度补齐-20261116.md`（7.4 KB）

**问题**：提示里能追问「保修几年」，问了答不知道。

**根因**：参数页里 **60 台有「质保时间=2年」**，但 `zol_map_fields.py` 的映射表没收录这个键。
顺着扫了一遍，漏的不止保修——还有续航、厚度、触控、系统、蓝牙、摄像头、音频、键盘、材质、上市时间，**共 15 个维度**。

**四层都漏了**：数据 → `core._pool_to_offer` → `agent.answer_followup` → `agent._topic_facts`。

**三处硬编码把答案拦掉了**：`_topic_facts` 没有「售后」主题；
`_warranty_stretch` 审计误判（语料里没有「保修一年」四个字就判成扩大）；
兜底模板只看 `pros` 不认新字段。

### `对抗采样与LoRA训练集.md`（8.8 KB）

**真实账目**：路由层只有 149 条（不是 1490 条——那 1747 条标的是 `budget_action`，另一套体系）。

**三条补数据的路**：手写模板 152 条 / 维度组合 348 条 / 真实日志 17 条。

**三方标签校验**发现 42 条「代码词表漏」（`CAP` 只枚举了「能跑/能打」，
漏了「能做/能剪/够跑/能撑」——枚举式判据的固有限制，而模型能泛化）。

**结果**：路由层 387 条，离 500 下限差 113。
