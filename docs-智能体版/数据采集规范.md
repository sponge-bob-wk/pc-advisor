# 数据采集规范

> 生成于 2026-11-11。回答两个问题：**数据从哪采**、**采哪些维度**。
> 配套文件：`data/prices.json`（数据）、`tools/build.py`（校验）、`数据溯源清单.md`（逐条来源）

---

## 一、数据源清单（按可靠性排序）

### 1.1 官方一手库（最优先）

| 站点 | URL | 能拿到什么 | 可用性 |
|---|---|---|---|
| **Geekbench Browser** | `browser.geekbench.com/processor-benchmarks` | CPU 单核/多核官方天梯 | ✅ 可直接抓 |
| **Geekbench 单型号页** | `browser.geekbench.com/processors/<slug>` | 某颗 CPU 的全部公开结果 | ✅ 可直接抓 |
| **3DMark 结果库** | `3dmark.com/search` | 按 GPU/CPU 筛 Time Spy 等 | ⚠️ 需 JS 渲染 |
| **UL 硬件库** | `benchmarks.ul.com/hardware/gpu/<name>` | 显卡 3DMark 分 | ⚠️ **只有桌面卡** |
| **UL CPU 库** | `benchmarks.ul.com/hardware/cpu/<name>` | CPU 的 3DMark CPU Profile | ✅ 部分可用 |

**两个必须知道的限制：**

**限制一：Geekbench 官方天梯已是 Geekbench 7。**
2026 年 11 月访问 `processor-benchmarks`，返回的是 GB7 榜单。GB6 被官方标为 legacy，`browser.geekbench.com/v6/cpu/<id>` 页面会明确提示「legacy version, can only be compared with other Geekbench 6 results」。

而本项目数据用的是 **GB6**。所以现在有两条路：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 坚守 GB6** | 已有 17 颗 CPU 数据、新旧可比、GB6 样本量最大 | 不是官方当前推荐版本 |
| **B. 迁到 GB7** | 跟官方一致、数据更新 | 全部重采、与已有数据不可比、GB7 笔记本样本还少 |

**建议 A**，理由：选购决策看的是相对排序，GB6 的历史数据更完整；但必须在 `meta.perfBasis` 里写明「基于 Geekbench 6，官方已标为 legacy」。

**限制二：UL 官方库没有笔记本 GPU。**
`benchmarks.ul.com/compare/best-gpus` 列的是 RX 9070 XT、RTX 5080/5070Ti/5090/5070 **桌面卡**。笔记本版 RTX 5060 Laptop 在 UL 库里没有独立条目。

所以笔记本 GPU 的 Time Spy 只能靠**一手评测**（见 1.2）或二手聚合（见 1.3）。

### 1.2 一手评测（自己跑分的媒体）

这层的价值最高：**同一台机器上，CPU、GPU、屏幕、续航是同一套测试条件**，不会出现跨来源拼接。

| 站点 | 强项 | 备注 |
|---|---|---|
| **Notebookcheck** | 最严谨，每台机型都跑完整套；GPU 有 min/avg/max 三值 | 英文，中文机型覆盖少 |
| **PChome / IT之家 / ZOL** | 中文机型实测，R23 和 3DMark 都给 | 单机数据，换机可能不同 |
| **LaptopMedia** | 笔记本专项，含 TGP 和功耗墙 | 适合查「满血/残血」 |
| **Ultrabookreview** | 轻薄本专项 | 样本少但细 |
| **NOVA / 各家评测** | 旗舰机完整实测 | 如 290HX Plus 的 R23 38899 |

**用法**：查某台具体机型时，优先找它的**单机完整评测**，一次拿全 cb23 + gb6 + tsGraphics，口径天然一致。

### 1.3 二手聚合（只作交叉验证，不作主源）

| 站点 | 特点 | 风险 |
|---|---|---|
| cpu-monkey | 样本量标注清楚（如 2086 条） | 不知道原始来源，可能是混合口径 |
| nanoreview | 对比页做得好 | 同上 |
| topcpu / cputronic / hardwaredb | 覆盖广 | 同上，且不同站之间能差 15% |

**规则：聚合站只用来交叉验证一手数据。如果一手数据缺失，用聚合站的中位数，但必须在 `cb23Source` 里注明是「聚合中位数」。**

### 1.4 电商（价格与规格）

| 渠道 | 能拿到 | 限制 |
|---|---|---|
| **京东商品页** | 价格、SKU 配置、净重、屏幕、电池、接口 | 直连被验证码拦，靠搜索索引拿页面摘要 |
| **淘宝/天猫** | 同上，价差可能更大 | 同上 |

**价格必须记三层**：`priceList`（页面标价）、`price`（常规到手）、`priceBest`（叠券最低）。原因见 §4.3。

## 二、数据维度（完整清单）

数据分三层：**机型（offer）** → **品类（category）** → **元信息（meta）**。

### 2.1 机型字段（33 个，36 条全覆盖）

#### 标识与分类

| 字段 | 类型 | 说明 | 采集来源 |
|---|---|---|---|
| `id` | string | 唯一标识，如 `thin-zhan66` | 自建 |
| `name` | string | 机型全名 | 商品页 |
| `brand` | string | 品牌 | 商品页 |
| `cat` | enum | `thin` / `gaming` / `desktop` / `upgrade` | 自建 |
| `useCases` | string[] | `office` / `study` / `dev` / `video` / `gaming` / `upgrade` | 判断 |

#### 价格（三层结构）

| 字段 | 类型 | 说明 |
|---|---|---|
| `price` | int | **常规到手价**（含国补，不含限时券） |
| `priceList` | int | **页面标价** |
| `priceBest` | int | **叠加店铺券/直播间券后的可及最低价** |
| `priceStatus` | enum | `verified`（核到京东页）/ `reported`（清单参考价）/ `pending` |
| `priceNote` | string | 该价格对应的具体 SKU 与优惠构成 |
| `channel` | string | 京东 / 天猫 |

**不变式**：`priceBest ≤ price ≤ priceList`，`build.py` 强制校验。

#### CPU

| 字段 | 类型 | 说明 | 采集来源 |
|---|---|---|---|
| `chip` | string | CPU 型号 | 商品页 |
| `cb23` | [int,int] | Cinebench R23 单核/多核 | 一手评测 > 聚合 |
| `cb23Source` | string | **R23 的确切出处**（新增，仅 5 条有） | 手工标注 |
| `cpuSustained` | int | **持续性能分** = `100×(0.5×单核/2400 + 0.5×多核/40000)` | 由 cb23 算出 |
| `gb6` | [int,int] | Geekbench 6 单核/多核 | 一手/官方 > 聚合 |
| `cpuBurst` | int | **爆发性能分** = `100×(0.5×单核/3400 + 0.5×多核/22000)` | 由 gb6 算出 |

#### GPU

| 字段 | 类型 | 说明 | 采集来源 |
|---|---|---|---|
| `gpu` | string \| null | 显卡型号 | 商品页 |
| `tsGraphics` | [int,int] \| null | **Time Spy Graphics** 最小/中位 | Notebookcheck 为主 |
| `gpuPerf` | int \| null | **GPU 性能分** = `100×图形分/25000` | 由 tsGraphics 算出 |
| `tgp` | int \| null | 显卡功耗上限（W），判断满血/残血 | 评测 / 商品页 |
| `gpuSource` | enum | `measured` / `inferred` / `none` | 判断 |

**必须用 Graphics 分，不能用 Time Spy 总分** —— 总分含 CPU 贡献，混用等于用错的尺子量。

#### 机身与使用

| 字段 | 类型 | 说明 | 当前覆盖 |
|---|---|---|---|
| `spec` | string | 配置摘要（**必须写全 SKU**） | 36/36 |
| `weightKg` | float | 净重（kg） | 14/36 |
| `screenInch` | float | 屏幕尺寸 | 30/36 |
| `batteryHour` | float | 续航小时（笔记本专用） | 1/36 |
| `loadWatt` | int | **整机满载功耗**（宿舍限电判断依据） | **0/36** |
| `upgrade` | 0\|1\|2 | 可加装程度（内存/硬盘位） | 36/36 |
| `portable` | 0-2 | 便携档 | 36/36 |

#### 评价

| 字段 | 类型 | 说明 |
|---|---|---|
| `pros` | string[] | 优点（必填，构建校验） |
| `cons` | string[] | 缺点（必填，构建校验） |
| `defect` | string \| null | 已知设计缺陷（如低温锡虚焊） |
| `lastChecked` | date | 该条数据的取数日期 |

> ⚠️ **`pros` / `cons` 没有数据来源，是编辑判断**，不是事实。产品里必须标注。

### 2.2 品类与权重

| 品类 | 维度 |
|---|---|
| `thin` 轻薄本 | price, cpuSustained, cpuBurst, gpuPerf, upgrade, portable |
| `gaming` 游戏本 | 同上 |
| `desktop` 台式 | price, cpuSustained, cpuBurst, gpuPerf, upgrade |
| `upgrade` 内存固态 | **只有 price**（三个性能维度全是 null） |

**六个侧重**（每个侧重有自己的权重表和主维度）：

| 侧重 | 主维度 | 对应人群 |
|---|---|---|
| `value` 省钱优先 | 无（综合分） | 预算极紧 |
| `daily` 日常流畅 | `cpuBurst` | 文科/商科，开软件切标签 |
| `carry` 便携优先 | `portable` | 经常背着跑 |
| `future` 能加装 | `upgrade` | 四年不换 |
| `work` 重度生产力 | `cpuSustained` | 剪视频、编译、仿真 |
| `game` 游戏优先 | `gpuPerf` | 打游戏 |

权重表在 `prices.json` 的 `categories[].weights`，每张表权重和为 1，`build.py` 校验。

### 2.3 来源（sources）

每条来源 6 个字段：`id` / `title` / `publisher` / `date` / `url` / `usedFor[]`

`usedFor` 列出这条来源支撑的具体数字，如 `["R7 H255 R23 1709/15475", "Radeon 780M 3077"]`。

### 2.4 元信息（meta）

| 字段 | 作用 |
|---|---|
| `version` / `updated` | 版本与数据截止日 |
| `scope` | 覆盖范围（中国大陆，仅电脑） |
| `priceBasis` | **三层价格的口径说明** |
| `perfBasis` | **三把尺子的换算公式与锚点** |
| `subsidyBasis` | 国补规则（电脑归家电类） |
| `disclaimer` | 免责与数据限制 |
| `dataStatus` | 当前覆盖度与缺口 |
| `generatedBy` | 生成方式 |

## 三、采集流程（按顺序做）

```
① 定机型
   来源：销量榜 / 选购清单 / 电商热销，不靠拍脑袋
   ↓
② 查 CPU 与 GPU 型号
   来源：京东商品页（最准）+ 厂商官网
   ⚠️ 同名机型多 SKU，必须记配置
   ↓
③ 查跑分（一手优先）
   有单机完整评测 → 直接用（cb23 + gb6 同机同测）
   没有 → cb23 取一手、gb6 取官方库
   都没有 → 取聚合中位数，并在 cb23Source 注明
   ↓
④ 查价格（三层）
   京东页面价 → priceList
   国补后价 → price
   叠券极限价 → priceBest
   ↓
⑤ 查机身参数
   重量、屏幕、电池、内存/硬盘插槽（商品页字段）
   ↓
⑥ 写优缺点（编辑判断）
   必须基于 ②③⑤ 的数据，不能凭空
   ↓
⑦ 跑 build.py 校验
   分数推不出 / 三层价格顺序错 / 同 CPU 不同分 → 构建失败
   ↓
⑧ 自动备份到 E 盘
```

## 四、四条取数规则（解决已知的数据错误）

### 4.1 跑分：同一台机器的单核多核必须来自同一次测试

**反面案例（已修正）**：R7 H255 的 R23 原来写 `2055 / 15475`，单核取自百度百科、多核取自 PChome。两个数不属于同一个测试条件。

**正确做法**：优先用同一篇评测里的完整数据。PChome 实测 WIKO Hi MateBook 14：`1709 / 15475`。

### 4.2 分数必须能由跑分推出

`build.py` 会算：`cpuSustained` 与 `cb23` 换算值差 >1 分就失败。手改分数不改依据，构建直接红。

### 4.3 价格三层不可合并

同一 SKU 实测能差 20% 以上（战 66：标价 5799 / 常规 5749 / 国补后 4674）。只存一个数，用户会以为别人买贵了或自己被骗。

### 4.4 不适用必须显式 null

内存条没有 CPU、没有 GPU，三个性能存 `null` 并从加权摘除。判 0 分等于「因为不涉及所以它最差」。
